块竞品做法我们的做法结论理由
三货架结构（推荐 / 上新 / 热门）首页主体就是三个货架三个货架同上，命名照它、口径用我们的（平台主推 / 新上架 / 销量优先）学货架 = "把在架商品按三种理由摊开"，直接提升首屏可下单密度；三个口径业务上互不重叠
货架标题 = 166rpx 图片标题标题是一张图（image + imageWidth）A 套：18 号文字标题 + 11 号品牌色小标（推荐）；B 套：同尺寸图形标题牌学结构不学形式图片标题要额外 3 张 ×2 倍图资产；改文案要改图；无法被搜索、无障碍读出；我们的品牌语言允许用实色小标做层级（白底为主 + 实色）
每条商品带封面（withCover）卡片左侧一律封面货架卡不放封面列，封面留给商品列表 / 详情页不学（本轮）实测在架 8 个商品里 7 个 coverUrl=null → 放封面列会让 7 行留空框（违反「不存在的东西不出现」），且真实商品名 20–50 字，再挤掉 88dp 会让名称更早截断
货架内纵向成列纵向成列，一屏 1–2 条纵向 ListCard 行（无圆角 + 发丝线）学真实商品名最长 46 字，横向卡必然截断；纵向行可左对齐名称、右对齐价格与下单；与竞品已验证的密度一致
「查看更多」→ 独立货架页/pages_ot/shelf?shelf=recommend→ 我们的「商品列表页」带 shelf 筛选（不新建页面）学结构改口径我们已有商品列表页且支持分部/分类筛选，再加一个 shelf 参数即可；复用页面比新建独立货架页更少维护面
空态文案「暂无推荐陪玩」/ 到底「没有更多了」一句话空态空态行写原因（平台还没配主推单 / 最近 7 天没有新增上架 / 还没有产生销量）+ 下拉刷新提示学语义改口径docs/21：空态要给下一步动作且文案具体可验证；我们的三货架空因不同，一句通用文案浪费了"告诉运营哪里没配"的机会

两个"待负责人选"的点

A 套 vs B 套（货架标题）
推荐 A 套（文字标题 + 品牌色小标）：① 零新增图片资产，改文案不改图；② 文字可被搜索/无障碍读出，长标题（如"热门点单 · 销量优先"）不会因为图片宽度 166rpx 挤爆；③ 与"白底为主 + 实色"一致 —— 图片标题通常要带底/描边才压得住，反而是额外装饰；④ 一致性问题：若 3 个标题是 3 张图，将来加第 4 个货架就要再出 1 张图。
B 套的代价：3 张 ×2 倍图资产；改一个字的标题要重新出图；截图/分享里标题是图（不可复制）。若负责人要视觉更"重"的标题，可折中：只给"为您推荐"这一个货架用图形标题牌（其余两个用文字），即 B 的最小剂量版。
货架内：横向滑动 vs 纵向列表
推荐纵向 ListCard 行：① 实测最长商品名 46 字（44.6博弈鹰雕单（出反现小金人+金aug或雪隼）不出保1200w[老板必须全程录屏不录开出不算]），横向卡宽 150–180dp 只能放 2 行 × 8 字 = 16 字，必然严重截断；② 价格、计价单位（/单、/局）、下单入口需要横向对齐才有"比价"的秩序感；③ 纵向行能天然承载"无封面"降级，横向卡则必须给空封面框；④ 竞品首页也是纵向，这条已被它的运营数据验证；⑤ 首屏高度不靠"改横向"省，靠"每货架行数 + 查看更多"控制。
否决横向的理由一句话：横向只省首屏高度，代价是"名称看不全"——而名称正是我们唯一的商品说明（subtitle 实测全空）。
宣传图与货架的衔接：宣传图下面第一块是货架还是分部
建议：货架在前、分部在后。① 负责人本轮指令是"把服务页做成货架结构"，首屏价值最高的就是能直接下单的商品；② 分部是"筛选/导航"而不是"内容"，用户从货架点进商品即可下单，下单页本身也有分部/平台选择 → 不必先选分部；③ 竞品首页第一块内容也是货架；④ 分部卡不删，只是下移，且「查看更多 → 商品列表页」内仍有分部筛选 → 入口没有重复。
紧贴体（0 间距）仍归宣传图（10-14 定案）。注意：10-06 定案曾把紧贴体让给充值入口条 → 两条定案冲突，需负责人二选一（本图按 10-14 定案：宣传图紧贴导航）。
右下「快速下单」浮标
建议删除：底栏中间凸起「＋下单」已经是下单入口，浮标是第二个同类入口（严格按「同一入口只出现一次」它本不该同时存在）；且实测它会遮住最后一行货架卡的右侧（价格与「下单」按钮所在区域）。本设计图按"删除"绘制。若要保留，需改成不遮挡的形态（例如只在滚动到底部时出现）。
