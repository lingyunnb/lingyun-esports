0. THE ONE THING USERS NEED TO KNOW  (the whole point of this directory)
------------------------------------------------------------------------------
The canonical fixed public host (the ngrok fixed domain) is still blocked by
its monthly bandwidth quota, so an OLD installed client cannot reach the update
server by itself right now. Therefore:

    Old-version users scan ONE of the "TEMPORARY ENTRY" QR codes below,
    install this build ONCE, and after that they never need a QR again.

Why "never again": the App carries multi-source address discovery (built-in
candidate list + self-hosted /site/client-config.json + Gitee/GitHub raw
bootstrap) and hot-switches to a working address by itself when a tunnel
address dies. The QR code is only a bootstrap for clients that predate that
capability.

WHAT CHANGED FOR USERS THIS RUN (boss only): the first thing you see when you
open the app is now a clean white brand splash (mountain mark + "QilianShan
Esports"), and the app background behind every page is a flat cold grey-blue.
Before this build, the first moment could look like a washed purple/pink/blue
glass gradient with soft blobs, which read as "the app is stuck" (it was not).
Nothing else changed; every other screen keeps its layout, and the worker
channel did not move.

WHAT CHANGED LAST ROUND (boss only, kept for history): chat images and
complaint screenshots really render again (they used a route that does not
exist and were missing the auth header), and the recharge-review proof image
shows a Chinese reason plus a retry button instead of spinning forever.

WHAT CHANGED LAST ROUND (boss only, kept for history): if the handler identity
was re-bound (or switched between accounts) while the order hall was showing an
error, the hall used to keep showing that stale banner with a "retry" button
until the user tapped it; the fixed build watches the identity generation and
re-fetches the division chips and the hall by itself.

WHAT CHANGED TWO ROUNDS AGO (boss only, kept for history): in handler state the
order hall's division chip row failed to load for EVERY handler account - it
showed "division list failed to load (not logged in)" and the retry button
could not help. The cause was a missing login token on one protected request
(GET /worker/division-permissions); v1.11.27 restored the chips.

WHAT CHANGED BEFORE THAT (worker only, kept for history): the worker app is the
FULL-BLOCK build. On launch it shows "the worker app has stopped service,
download the QilianShan Esports app and bind your worker account under
Me -> Identity to keep taking orders" and offers ONLY the download button -
the old "keep using for now (7 days)" escape hatch is gone, and the copy no
longer mentions any date (immediate effect). The worker update channel is kept
alive on purpose so that anyone still running an older build receives this
blocking build the next time they open the app.

4. HOW THE QR CODES WERE MADE THIS RUN (and how to redo it)
------------------------------------------------------------------------------
This run used the repo's OWN self-contained encoder (scripts/tools/qr-encode.js,
no network) instead of `npx --yes qrcode`: scripts/tmp/_regen-qr-boss-v89.ps1 reads
the absolute download URL from scripts/tmp/_qr-url-apk-boss-v89.txt and the
Chinese caption from scripts/tmp/_qr-cap2-v89.txt (both UTF-8, no BOM), encodes
