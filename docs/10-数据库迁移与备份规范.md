# 10 - 数据库迁移与备份规范

## Migration 纪律

1. 结构变更一律 TypeORM migration（server/src/migrations/），**禁止 synchronize: true**
2. 命名：`{时间戳}-{动作}-{表名}.ts`（如 1726800000000-create-order-tables.ts）
3. 一次 migration 只做一件事；含 down 方法（可回滚）
4. 兼容顺序：先加列（可空/有默认值）→ 发布 → 数据回填 → 再收紧约束；不直接删列
5. 执行：开发 `npm run migration:run`；执行前后记录到当日开发日志
6. 表结构权威文档 docs/02 与 migration 同步更新

## 备份（infra/scripts/backup-db.ps1）

- 方式：`docker exec` mysqldump `--single-transaction --routines --triggers --no-tablespaces`（InnoDB 一致性快照，不锁表）
- 频率：每日一次（计划任务，M9 配置开机/每日自启）
- 压缩：zip 归档到 **data/backups/**fish_YYYYMMDD_HHmmss.zip（D 盘数据目录）
- 保留：14 天，超期自动清理
- 备份完成后校验压缩包可解压、SQL 尾部有 dump 完成标记

## 恢复（infra/scripts/restore-db.ps1）

1. 指定备份文件 → 自动解压 → `docker exec -i` 导入
2. 恢复前自动再备份一次当前库（安全网）
3. 恢复后校验：核心表行数抽查（user/wallet/order/wallet_transaction）

## 恢复演练

- M9 强制完成一次全流程恢复演练，结果记录到开发日志（未演练的备份等于没有）
- 演练标准：恢复后服务可启动、登录可用、抽样数据一致
