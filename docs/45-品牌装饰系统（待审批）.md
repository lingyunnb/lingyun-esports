## 一、为什么这些装饰能"一眼看出是同一套"（一句话内核）

> **一套装饰 = 一条 45° 刀口 + 一张 4dp 网格 + 三档尺度的色彩用量。**

「一眼认出」不靠多画元素，靠**三个重复量**：

1. **角度重复**：全站所有斜切角都是 **45° 直线**（没有圆角切口、没有弧形、没有三角形贴片），只有 **6×6 / 8×8 / 4×4** 三级，级差由元素高度决定（≈ 高度 ÷ 4），不由审美决定。
2. **落格重复**：装饰的每个尺寸与间距都是 **4dp 倍数**（切口 6/8、端点 3×3、标尺到内容 8、线到内容 12、区块间 20、页边 16），所以跨页面时"节奏"同一。
3. **色彩尺度的重复**（负责人 2026-10-15 放宽颜色后新加）：颜色不当填色板，当**三档音量** ——
   **第 1 档极浅底**（`#E8EEF7 / #E3F0EF / #F7EDE0 / #F4F6F9`）打底 · **第 2 档实色与描边**（`#1D5FA8 / #0E7C7B`，金 `#B4732A` 只给价格与等级）**定位** · **第 3 档极小面积品牌锚**（`#0F2440`，每屏 ≤1600px²）**落徽**。
   任何一个装饰元素用色，都能说出它属于哪一档 —— 说不出就不加。

**元素变少时靠什么撑住识别度（本题核心的正面回答）**：陪玩/打手的展示字段被收窄到「头像 + 名字 + 介绍 + 接单次数 + 好评率」后，页面上能挂装饰的地方只剩 **区块标题 · 数字与金额 · 筛选胶囊与分段 · 空态/骨架/分隔**。
此时识别度不来自"更多元素"，而来自**这三件事被更严格地重复**：**① 唯一种类的 45° 刀口**（元素越少，它越显眼）· **② 三档色彩尺度**（白底上一处重点，不摊大色块）· **③ 线的分工与 4dp 节奏**（发丝线管行、标尺线管区块）。
缺任何一件，页面都会同时"元素少"且"没有品牌" —— 这就是本题真正的难点。

## 二、6 个装饰位（规则 · 依据 · 与既有组件对接）

> 「对接方式」列：**新加** = 需新增组件/类；**扩展现有** = 改既有组件的装饰层，语义与 API 不变；**不动** = 既有实现逐字保留。

### ① 页面骨架 —— 5 条横基准线 + 2 条纵基准线

| 基准线 | 位置 | 允许挂什么装饰 |
|---|---|---|
| **B0 页头底线** | `y=104`（状态栏 48 + 页头 56） | 页级标尺线（**无左端点方块**，示意"页级分隔"） |
| **B1 品牌区底线** | `y=168`（+ 品牌区 64） | 品牌区细网格（1px，5%）只到这一条，不越界到内容区 |
| **B2 首块内容线** | `y=188`（+ 区块间 20） | 内容停靠线，**装饰不许压在上面** |
| **B3 区块间线** | `y=288`（+ 内容块 80 + 区块间 20） | 区块标尺线（**左右端点齐备**） |
| **B4 页底信号线** | `y=788`（844 − 页底 56） | 页底标尺线（**带左端点方块**，示意"这一页到此结束"） |
| **V0 / V1** | `x=16 / x=374`（栏宽 358） | 所有贴线装饰左端从 V0 起；行内发丝线缩进 16 与 V0 对齐；不越 V0/V1 |

- **依据**：`docs/32 §六`（卡片三档）+ `docs/39 §五`（组件高度档：页头 56 / 底栏 56 / 品牌区 64）+ 4dp 网格。
- **它解决什么问题**：装饰不再"随手放"，而是"贴线放" —— 这是"不堆砌"的机械保证。
- **去掉会怎样**：装饰会按每页各自的感觉摆放，跨页一致性立刻丢失；且页尾没有收口信号，用户不知道"到底了"。
- **对接**：**新加** `AppBaseline`（基准线常量：`b0/b1/b2/b3/b4/v0/v1`，只读常量类）· **不动** 任何页面布局。

### ② 卡片语言 —— 三档卡片各自的唯一装饰特征

| 档 | 唯一特征（互相不可替换） | 依据 |
|---|---|---|
| **HeroCard**（每屏 ≤1） | 白底 + `#E8EEF7` **细网格** + **右上 24dp 墨蓝字标块**（品牌锚） | `docs/32 §六` 的 HeroCard + `docs/39 §二` 的"取消深色 HeroCard，改白底 + 品牌色描边" |
| **ContentCard** | 白底 + 1dp `#E3E8EF` 描边 + **圆角 14** + **左下 6×6 切口** + 标题前 **4×16 品牌短标** | 同上；切口 = 本次新增装饰层 |
| **ListCard** | 通栏白底 + 上下 1dp 发丝 + **圆角 0** + **行高 48/56/64**（**无切口**，序列表格没有"角"的语义） | `docs/21 §四`「列表优先于卡片阵」 |

- **为什么"一眼是同套"**：三档的第一眼区别是**形态**（网格块 / 描边圆角卡 / 通栏行），第二眼是**同源切口**（只出现在 ContentCard 与标签上，位置随语义固定）。
- **去掉会怎样**：三档卡片会退化成"三个都是白圆角矩形"——`docs/32 §六` 明令打破的正是这一点。
- **对接**：**扩展现有** `AppCard`（加 `level: hero|content|list` 与装饰开关 `deco: none|corner|grid`；既有默认值保持"content"→ 现有调用处行为不变）· **新加** `AppLevelSlot`（L-SLOT，见下）。
- **L-SLOT（等级标识预留位 · 负责人新要求）**：**只锁几何、不锁内容** —— 位置在名字**同一行右侧**，**高 20 × 最长 72**，与名字间距 **8dp**，垂直居中；形态未定，名称确定后按第 ⑤ 节规则落地（20 高 → 右上 6×6 切口 / 字号 11 / 字重 700）；**若名称含等级语义，它是全站除价格外唯一允许上金的位置**。列表行已按 24dp 行高预留（名字 15sp 行高 20 + 4dp 余量），补内容时不改版式、不挤行。
  本轮图上以**琥珀虚线空框 + 尺寸标注**呈现，**不画形态、不起名字**。

### ③ 区块标题 —— 在既有 `AppSectionHeader` 上只加"一条线 + 一个短标"

- **规则**：标题左侧加 **4×16 品牌短标**（高 = 字号 15 的 16dp，宽 4dp，落格）；标题下方 **8dp** 处加 **标尺线**（1dp 发丝 + 左右各 3×3 端点方块）。右侧动作沿用既有 12sp 品牌蓝。
  **短标数量 = 该页顶级分区数**（服务页 = 2：游戏分类 / 官方自营馆；"重点商品"是第二层 → **只有线、没有短标**）。
- **为什么不像"每段配个彩色小标签"**：标签是"**必须区分的项**"专用（平台/状态/价格）；标题本身不需要被区分，所以它拿到的是**线**而不是**色片**。浅底块 + 左侧竖条属于`docs/21` 点名的"靠彩色小片堆砌层级"，本方案**同时只给一个信号**（线），分组底色与卡片上边框都取消。
- **去掉会怎样**：区块层级只剩字号差（15 vs 13），在两三个区块相邻时读不出"这是新的一段"。
- **对接**：**扩展现有** `AppSectionHeader`（加 `deco: bool = true` 与 `accent` 可选色，默认开启；传 `false` 时输出与现状逐字节一致）。

### ④ 数字与金额 —— 装饰靠"三件事"，金只有一处

- **规则**：`tabular-nums` 等宽 + **三级字号档 15 / 18 / 22 配 w700** + `¥` 与单位走 **12sp / w600 贴基线**（`align-baseline`，符号比数字小 ≥2 档）；单位（`/局`·`/小时`）用 **`#8A99AB`**（与金额**不同色**，否则单位会被读成钱）。
  金额格式恒为 **`¥` + 两位小数 + 千分位**（`¥28.88` / `¥115.52` / `¥4,286.50`），且**整串可命中**（不能用独立小号 Text 拼）。
- **金的唯一性怎么守**：金 `#B4732A` 只允许出现在 ① 金额数字与 `¥`；② **等级徽章 / L-SLOT（等级标识）**。**统计类数字（单量 / 在线数 / 次数 / 时长）一律 `#14202E`**；促销语气改用文案表达，**不引入 `#D4A017` 这类"更亮的金"**（引入即等于出现第二个金）。自检口径：**金色文字出现处里，凡不在金额/等级容器内即算违规**（脚本实测 = 0）。
- **依据**：`docs/32 §一` 铁律 3 · `docs/32 §四`（金额数字行）· `docs/39 §四`（品牌色出现位置全清单）。
- **对接**：**扩展现有** `AppPrice`（加 `unitColor` 与 `size: sm|md|lg` 三档映射 15/18/22；**价格串仍由 `fmtMoney` 产出，页面不拼 `¥`**）· **新加** `AppStat`（灰黑统计数字，与 `AppPrice` 物理同屏时不允许上金）。

### ⑤ 状态与标签 —— 把"右上 6×6 斜切角"扩展成一套语言（**同源扩展**）

**五档 × 四信号**（图标 + 形状含右上 6×6 斜切角 + 字重 600/700/800 + 颜色）**保持逐字不变**（`apps/boss-app/lib/widgets/order_status_tag.dart`，本次零改动）。本次扩展的是同一条切口语言：

**斜切角语言谱系图**：`45° 切口 ── 6×6（h20–24，右上｜状态·归属） ── 8×8（h32，右下｜选中·进行） ── 4×4（h16–20，右下｜最小号/方向）`

| 装饰位 | 切口 | 角位 | 语义 / 为什么是这个角位 | 对接方式 |
|---|---|---|---|---|
| 订单状态标签 | 6×6 | 右上 | 状态是"被判定"的结果，右上 = 结论位；五档四信号已定案 | **不动**（`OrderStatusTag`） |
| 分区标签（分部/平台/区服） | 6×6 | 右上 | 与状态标签同形 → 归入"标签"类；但底色恒 `#F4F6F9` + 灰字，不抢状态色 | **新加** `AppMetaTag` |
| 筛选胶囊 · 选中 | 8×8 | 右下 | 胶囊高 32（比标签高一档）→ 切口同步升一档；右下 = 选中"向前"的方向感 | **扩展现有** `AppTagChip`（只加装饰层，选中判定与回调不变） |
| 分段控件 · 选中段 | 4×4 | 右下 | 分段是"切出一段"，切口最小且贴段方向；**不做整条切角**（会与胶囊撞形） | **扩展现有** `AppSegmented`（同上） |
| 小角标（起 / 已接 N 单） | 4×4 | 右上 | 高 16 的最小号，缩到 6×6 会把字吃掉半边 | **新加** `AppMiniBadge` |
| **卡片**（ContentCard） | 6×6 | 左下 | 左下角是"块内起点"，与右上标签正好成对角，视觉上互不干扰 | **扩展现有** `AppCard` |
| **L-SLOT（等级位）** | 6×6 | 右上 | 与状态/分区标签同档同形，名称确定后直接落 | **新加** `AppLevelSlot` |

- **硬规则两条**：① **未选中态一律不切口**（切口是"选中/状态"的专属信号，两边都切就退化装饰）；② **切口边长 ≈ 高度 ÷ 4，只取 4 / 6 / 8**（尺寸与高度脱钩会变成"缺了个角/被咬掉"）。
- **实现沿用既有思路**：**底色盖角 + 只画两条边**（不引入 `ClipPath` 真裁，避免描边被裁断、在任意底色上出现缝隙）——与 `OrderStatusTag` 现有实现完全一致。
- **依据**：`docs/32 §二` 辅助图形①斜切角（"每屏 ≤4 处"在扩展后按"**每屏 ≤1 类**：标签类 / 胶囊类 / 卡片类 各计"口径执行，具体值见 §四自检）。
- **去掉会怎样**：状态标签的斜切角会变成"一个孤立的怪角"；扩展成语言后，它成为全站识别度最高的形状记忆点 —— **这正是元素变少时最有效的锚**。

### ⑥ 空态 / 加载 / 分隔 —— 不靠插画的品牌感

- **三件套**：空态 = **5% 细网格底 + 48×48 线框图标（右上 6×6 切口）+ 标尺线 + 一句下一步动作**；骨架 = **6 档灰阶底 + 40% 宽 / 白 55% 的亮带扫过**；分隔 = **发丝线管行、标尺线管区块**。
- **分工判据（一条就够）**：**看这条线/纹理要表达"内容结束了"还是"这里还没有内容"。**
  - **发丝线**（1dp `#E3E8EF`，**无端点方块**）→ 内容**行**分隔，缩进 16 对齐文案起点；
  - **标尺线**（1dp + **3×3 端点方块**）→ **区块 / 页面**分隔，是"结构"的线；
  - **细网格**（1px，**3–5%**）→ 只出现在"还没有内容"的两处：**品牌区背景 + 空态背景**，其余区域 **0 处**。
- **骨架不跳版**：骨架块**保留真内容的圆角与内距**（卡 14 / 通栏 0 / 磁贴 56 / 卡内 12），亮带克制（40% 宽、白 55%）。
- **依据**：`docs/21 §五`（必须设计空态/加载/错误态）、`docs/21 §二`（列表用发丝线、装饰插画一律删）。
- **去掉会怎样**：空态只剩一句灰字（像坏了）；骨架用胶囊圆角 → 加载完成瞬间整块"跳一下"。
- **对接**：**扩展现有** `AppEmpty`（加细网格底 + 线框图标切口，文案与动作 API 不变）· **新加** `AppSkeleton`（shimmer 亮带与形状规范）· **不动** `AppHairline`。

## 三、配色使用规则表（负责人 2026-10-15 放宽"可以用颜色"后的落地）

**读法先说明**：「白底为主」与「可以用颜色」**要一起读** = **底色仍以白为主（页底 `#F4F6F9` / 卡面 `#FFFFFF`），装饰元素可以大胆用色** —— 不是"可以铺大块深色底"。
这个读法同时解释了 `docs/32` 铁律 1（"渐变面积 ≈ 0 → 品牌区一律用实色深块"）与 `docs/39`（"取消一切整块深色/蓝色大块"）：两处说的是**底色**，不是**装饰元素的用色**。
**若负责人另有读法**（例如允许整块深色品牌区），只需改本表第 1 行的"面积上限"与 §四的占比自检阈值，设计结构不受影响。

| 色 | 允许出现在哪 | 面积上限（每屏） | 与谁搭配 | 禁止组合 / 禁止位置 |
|---|---|---|---|---|
| **品牌锚墨蓝** `#0F2440` | 40dp 字标块底 · 品牌署名徽章 1dp 描边 | **≤1 处 / 屏**，≤1600px²（约首屏 0.5%） | 白字 · 8×8 品牌蓝小切口 · 发丝线 | 不作卡面/区块底/页头底；不与其他深色相邻成大块；不做渐变端点 |

## 四、手段取舍表（以后所有人照着做）

| 手段 | 用 / 不用 / 有条件用 | 为什么 | 正例 → 反例 |
|---|---|---|---|
| **斜切角** | **用**（主符号） | 唯一的形状信号；45° 直线，不引入新形状词汇 | 状态标签右上 6×6 → 两角全切 + 真 `ClipPath` 裁断描边 |
| **细网格** | **用**（限量） | 给"还没有内容 / 品牌自己在说话"的地方一个质感底；3–5% 不干扰正文 | 品牌区底 + 空态底 → 铺到正文区 / 提到 20% 变"雪点" |
| **标尺线** | **用** | 区块分隔专用（两端 3×3 方块让层级可读），替代卡片上边框与分组底色 | 区块之间 → 用它分隔列表行（端点变噪音） |
| **图标底色** | **用**（通用做法） | 让 20dp 线性图标在列表里有一个"落点"，是列表行最容易的节奏来源 | 3 个分部行分用浅蓝/浅青/中性底 → 每行都换色 = 彩虹列表 |
| **分隔色带** | **有条件用** | 只在"整块内容自身要有一句话标签"时用；它承担**文案**不是分隔 | 通栏块下沿 24dp 浅底带 + 8×8 切口 → 用色带代替发丝线做列表分隔 |
| **色块底** | **有条件用** | 只允许**极浅底**（第 1 档）与**极小面积实色**（按钮/选中/字标）；色块永远做"底"不做"结构" | 浅底图标底 + 实色主按钮 → 整块品牌蓝卡面 / 深色 Hero 大块 |
| **彩色竖条** | **有条件用**（默认不用） | `docs/21` 点名"过时模板签名"。唯一窄口径例外：**通栏块的左边界标识条**（不属卡片）；卡片内一律改用 **4×16 短标** | ListCard 内 4×16 短标 → 每张卡左侧 4dp 竖条贯穿整卡高 |
| **阴影** | **有条件用**（默认不用） | 卡片用发丝线分界，阴影只承担"浮起来"的语义。允许处：**弹层 / 吸底操作条 / 悬浮按钮**；**卡片 0 阴影** | 弹层 1 处 6% 投影 → 每张卡 10% 投影铺满 |
| **渐变** | **有条件用**（默认不作主视觉） | 判据见下 | 骨架 shimmer（40% 宽浅白）→ 整块蓝→青渐变作页头/横幅主视觉 |
| **大圆角** | **不用**（≥16 当卡片） | 玩具感、软塌、层级消失；圆角只用 `4 / 6 / 10 / 14 / 胶囊`（手机壳 18 属设备外框） | 卡 14 + 控件 10 + 小片 4/6 → 卡片全部 18–24 圆角 |

### 渐变边界（明确划界）

> **块高 ≤ 64dp 且不承担信息层级 = 装饰性渐变（可以）；> 屏宽 40% 且高 > 200dp，或作为卡片/页头/横幅底 = 主视觉渐变（不行）。**
> 另加一条反面判据：**把渐变换成实色，若层级关系完全不变 → 它只是装饰性炫技**（那就必须缩小）。
> **自检口径**：脚本把**同位两个色标的硬边渐变**（细网格、shimmer、通栏 1px 条纹）单列为**纹理**，不计入"渐变面积"；只有**连续过渡**才计入，且实测 **= 0**。

### "通用做法"的三条准入

① 必须能说出解决什么问题；② 必须落 4dp 网格；③ 必须能在不改变结构的前提下删掉。三条缺一 → 不入系统（标"不用"）。

## 附、出图脚本踩坑留痕（供后人复跑，2026-10-15）

1. **`captureBeyondViewport:true` + clip 的陷阱（本次返工两次的根因）**：只要**视口高度 ≥ clip 目标高度**，Chromium 就会**忽略 clip 的 `height`** 整页出图 —— 实测 clip 写 3320/1533/3385，实得全是 8752/8000。
   正确做法：**保持默认视口（1420×1000）+ `clip.y` 用绝对偏移 + `captureBeyondViewport:true`**，实得高度才等于目标高度。
   脚本里另加了一道**自愈校正**：出图后读 PNG 头，若实得高度 ≠ 目标高度，就按实得高度**再截一次**（避免再次返工）。
2. **缩放长图别用 CSS `transform`**：`transform: scale()` 不改变布局尺寸，会导致截出来是"原尺寸画布 + 右下角缩小内容"。
   正解：**`Page.captureScreenshot` 的 `scale`（= deviceScaleFactor）**，布局不变、只缩小位图 → 总览图 `0.9118 → 1420×7294`。
3. **出图后必须读 PNG 头断言高度**：`IHDR` 在文件第 16 字节起 8 字节（大端 uint32），不引任何依赖；
   本次已把「高度 > 8000 直接 FAIL」写成断言 —— 审批图打不开等于没交付。
4. **分段图的 `clip.y` 用页面绝对坐标**：先量各段起点的 `getBoundingClientRect().top + scrollY`（本次关键点：③=3352 / ④=3770 / ⑥=5303），
   再按"段起点 `clip.y` + 段高"截取；每段顶部加一条深色说明条（`?banner=` 运行时注入，静态打开零影响）。
