> 的启用步骤。相关代码：`apps/packages/core/lib/src/config/app_address.dart`、

## 1 现状与实测（2026-10-06，本机 / 代表用户网络）

| 入口 | 实测 | 说明 |
|---|---|---|
| 本地 `http://127.0.0.1:3100` | **200** / 8ms | 后端本体，正常 |
| Cloudflare 快速隧道 `https://vista-bind-archives-components.trycloudflare.com` | **200** / 1.57s | `fish-tunnel` 已连续存活 42h；**域名每次重启会变** |
| ngrok 固定域名 `https://<your-tunnel-domain>` | **403 `ERR_NGROK_725`** | 账号**月度流量耗尽**，账号级故障；额度重置后自动恢复 |
| GitHub raw | **http=000 不可达** | 原 bootstrap 唯一来源 → **1.11.21 存量用户无法自动换址** |
| Gitee raw | **0.25s 可达**（仓库未建时 404） | 可作 bootstrap 第一源 |
| jsDelivr（GitHub 仓库 CDN 镜像） | **可达**（404 仅因仓库内暂无该文件） | 可作 bootstrap 第三源 |
| Sakura FRP 官网/API | **200** | 可作第二条固定入口（需负责人开号） |
| Tailscale 官网 | 200 / 10.3s（偏慢） | 暂不采用 |

**ngrok 额度为什么这么容易耗尽（重要）**：免费档约 1GB/月出口流量，而
`data/uploads/app-versions/` 里每个 APK 是 **26.3 MB（老板端）/ 21.8 MB（工作端）**
—— **一次云更新下载就吃掉 2.2%–2.6% 的月度额度，约 38 次下载即耗尽**。
因此"把 APK 下载挪出计量隧道"（见 §6）比省图片流量重要一个数量级。

## 2 地址发现链（客户端）

App **不是**把地址写死的，而是启动时按下面这条链自己找：

```
多源 bootstrap（按序尝试，任一成功即用）
  ① Gitee raw                    ADDRESS_BOOTSTRAP_GITEE（未配置则整条跳过）
  ② <候选>/site/client-config.json   ← 服务端自托管，不需要任何第三方账号
  ③ jsDelivr 镜像                 ADDRESS_BOOTSTRAP_JSDELIVR
  ④ GitHub raw（末位兼容）         ADDRESS_BOOTSTRAP
        ↓ 拿到 { api, ws, preferred, candidates }
  候选并行探活（GET <api>/health，要求 200 且正文是 FISH 统一响应）
        ↓ preferred（ngrok 固定域名）活着就用它；否则最快者胜
  写回 AppConfig.apiBase / wsBase（热生效）
        ↓ 全部引导源失败
  内置多候选（ADDRESS_BUILTIN_CANDIDATES）并行探活，最快者胜
        ↓ 仍全失败
  打包内置地址（API_BASE_URL 编译期常量）—— App 一定起得来
```

**运行期自愈**（`AddressWatchdog`）：启动解析失败、运行中连续 3 次请求失败、
或首次 WS 连不上 → 清缓存 → 重走上面整条链 → **热切换**地址（不要求重启 App）。
带指数退避（5s→10s→20s…封顶 5min）与**单进程 6 次上限**，全部不可达时不会死循环。

**为什么不只按延迟选最快**：快速隧道域名**每次重启都会变**，ngrok 固定域名不变。
只按延迟会把"今天恰好更快的临时隧道"选成主入口，隧道一重启又得重来一遍。
所以 JSON 里有 `preferred` 字段：**它活着就用它**；它死了（如额度耗尽 403）才退回最快者胜。

## 3 发布当前地址（日常操作，一条命令）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\fish\scripts\publish-address.ps1
```

它做四件事（只碰 FISH 资源）：

1. 从 pm2 日志 / cloudflared 日志 / 缓存文件解析出**当前**隧道地址；
2. 写 `config/client-config.json`（单一真相）—— `api` = 当前可用地址，
   `candidates` = **同时含** Cloudflare 隧道与 ngrok 固定域名，
   `preferred` = ngrok 固定域名（额度恢复后自动回到主位）；
3. 同步到 `site/client-config.json`（服务端同源托管 → `/site/client-config.json`，
   这就是"**不需要第三方账号**"的那条引导腿）；
4. 自检：`GET <api>/health` 必须是 200 且正文是 FISH 统一响应（防 ngrok 插页假 200），
   再验一次 `GET <api>/site/client-config.json`。

隧道重启后**重跑这一条命令**即可，不需要重新发版。

> ⚠️ `site/client-config.json` 是**运行时下发的配置产物**，必须入库
> （它是 bootstrap 源②的数据源；不入库则新机器/新部署拿不到当前地址）。

## 4 Gitee raw bootstrap 启用步骤（等负责人给凭据）

前置：负责人提供 Gitee 账号/组织名、仓库名（建议 `fish-endpoint`，公开仓库）、
以及一个 personal access token。**令牌只走环境变量，绝不写进仓库。**

```powershell
$env:GITEE_TOKEN  = '<负责人提供的令牌>'
$env:GITEE_OWNER  = '<账号或组织>'
$env:GITEE_REPO   = 'fish-endpoint'
$env:GITEE_BRANCH = 'main'

# 1) 先 DryRun（默认就是 DryRun，不会推任何东西）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\fish\scripts\tmp\publish-bootstrap-gitee.ps1

# 2) 确认输出里的 URL/分支/内容无误后，再真正推
powershell -NoProfile -ExecutionPolicy Bypass -File D:\fish\scripts\tmp\publish-bootstrap-gitee.ps1 -Apply
```

脚本会：校验 JSON 合法性 → 读旧 sha（存在则更新、404 则新建）→ POST 上传 →
再 GET 一次 raw URL 验证真的能读到同一份 JSON → 打印构建时要用的 `--dart-define`。

构建时启用（否则这条源被整条跳过）：

```
--dart-define=ADDRESS_BOOTSTRAP_GITEE=https://gitee.com/<owner>/fish-endpoint/raw/main/client-config.json
```

之后每次换地址：`publish-address.ps1` 跑完，再跑一次本脚本（或加进日常脚本）。

## 5 Sakura FRP 启用步骤（第二条固定入口，等负责人确认）

**已知结论（踩过的坑，必须先看）**：Sakura FRP 之前建隧道报 **501**，
原因是建成了**明文 HTTP 类型**隧道；**必须建 HTTPS/TLS 类型**（本地服务本身是明文
HTTP，由 frpc 与 Sakura 节点之间做 TLS 终结）。

照着做（6–8 步）：

1. 打开 <https://www.natfrp.com/> 注册/登录（官网本机实测 200 可达），完成实名（免费档要求）。
2. 进 **用户中心 → 隧道 → 新建隧道**；节点选**离用户近、延迟低**的（华南/华东各试一次）。
3. **隧道类型必须选 `HTTPS`（或 `TLS`）——不要选 HTTP**（选 HTTP 就是历史 501 的原因）。
4. 本地地址填 `127.0.0.1`，本地端口填 **3100**；「绑定域名」用一个自己可控的域名
   （Sakura 免费档通常要求自有域名并 CNAME 到它给的节点；没有域名则用它的免费二级域名，若有）。
5. 在 **用户中心 → 软件下载** 取 `frpc`（Windows x64）与你的**访问密钥**；
   把 frpc 放到 `D:\fish\infra\tunnel\`（与 cloudflared.exe 同目录）。
6. 在 Sakura 隧道详情页复制**生成的启动命令/配置**，写成 `D:\fish\infra\tunnel\frpc-sakura.toml`；
   用 `frpc.exe -c frpc-sakura.toml` 前台跑一次，确认日志里隧道**已启动**且没有 501/连接被拒。
7. 把它交给 pm2 常驻（**只加 FISH 自己的进程，不要动 OtherProject-\***）：
   ```powershell
   pm2 start D:\fish\infra\tunnel\frpc.exe --name fish-tunnel-sakura -- -c D:\fish\infra\tunnel\frpc-sakura.toml
   pm2 save
   ```
8. 验证并发布：
   ```powershell
   curl.exe -s -o NUL -w "%{http_code}\n" -H "ngrok-skip-browser-warning: true" https://<你的固定域名>/api/v1/health
   powershell -NoProfile -ExecutionPolicy Bypass -File D:\fish\scripts\publish-address.ps1 -Url https://<你的固定域名> -Preferred https://<你的固定域名>
   ```
   出包时把 `<你的固定域名>` 也加进 APK 的内置候选（`scripts/release-app.js` 会自动带上
   ngrok 固定域名 + 当前隧道 + 本机局域网 IP；要完全自定义就设
   `$env:FISH_BUILTIN_CANDIDATES="https://a,http://b"`，它会变成
   `--dart-define=ADDRESS_BUILTIN_CANDIDATES=...`）。

> 免费档注意：Sakura 免费隧道有**带宽/连接数限制**，适合做"固定入口 + 兜底"，
> 不适合扛 APK 下载这种大流量 —— 大流量请走 Cloudflare 快速隧道（不计流量）。

## 6 省流量（让免费额度够用）

按"省下来的流量"从大到小排：

1. **把 APK 下载挪出计量隧道（收益最大）**：一次云更新 26.3MB ≈ ngrok 免费额度的 2.6%。
   云更新已有 `mirror_url` 镜像机制（2026-10-06 多连接分片提速）：把镜像源指向
   Cloudflare 快速隧道（不计流量）或 Gitee/jsDelivr 托管的大文件，ngrok 只留 API。
2. **APK 瘦身（已量化，见 §6.1）**：MiSans 字体子集化 **7.58MB → 1.63MB（-78.5%）**，
   APK 内约省 **4.0MB**（-15.4%）。等于每次下载少烧 0.4% 额度。
3. **清理历史 APK**：`data/uploads/app-versions/` 现有 **112 个 APK / 2.77GB**，
   其中 4 个 2026-09-22 的旧包各 53–54MB。**删文件属数据删除，须负责人批准**。
   注意：只有"被下载"才产生流量，所以真正的动作是**确保旧版本通道已停用**（已停用），
   清理磁盘是次要收益。
4. **图片缓存 TTL**（已做）：`/media/public/:id` 缓存头由 `public, max-age=86400`
   改为 `public, max-age=2592000, immutable, no-transform`（2026-10-06）。
   安全性依据：落盘文件名是 `YYYY/MM/<uuid>.<ext>`，同 id 永不改写内容 → 真·不可变资源；
   `res.sendFile` 仍带 `ETag`/`Last-Modified`，条件请求返回 **304 / 0 字节**（实测）。
5. **服务端缩略图**：见 §6.2（**需要新增依赖 → 先出方案，等负责人拍板**）。

### 6.1 APK 体积构成与瘦身清单（实测）

老板端 `app-arm64-v8a-release.apk`（v1.11.21，26.29 MB）：

| 类别 | 解压后 | 压缩后 | 占比 |
|---|---|---|---|
| `lib/*.so`（`libflutter.so` 11.20MB + `libapp.so` 7.13MB + …） | 18.46 MB | 18.46 MB | 60.2% |
| **字体 `MiSans-Normal.ttf`** | **7.59 MB** | **5.13 MB** | 24.7% |
| `classes.dex` | 2.72 MB | 1.37 MB | 8.9% |
| `assets/` 其它 + `res/` + `arsc` | 1.90 MB | 1.23 MB | 6.2% |

对照：工作端 **21.80 MB**（无 MiSans 字体，`libflutter.so` 同样是 11.20MB）。

| 动作 | 预计节省 | 风险 | 建议 |
|---|---|---|---|
| **MiSans 子集化**（GB2312 全集 + ASCII + 标点，实测） | **约 4.0 MB（-15%）** | 中：子集外的字会变豆腐块 | 先跑覆盖率自检（对照数据库真实字符串）再决定；脚本已就绪 `scripts/tmp/subset-font.py` |
| `--split-debug-info=<dir>` | 约 5–15% 的 `libapp.so`（0.4–1.1 MB） | 低（需保留 `.symbols` 才能还原堆栈） | **建议开关式引入**（默认关，发版时按需开） |
| `--obfuscate` | 与上者叠加收益很小 | **高**：崩溃堆栈不可读，安全性审计/线上排障成本陡增 | **不建议开**（除非有明确的代码保护需求） |
| 分区/AAB 分发 | 每个用户少下别的 ABI（已 `--split-per-abi`） | 无 | 已完成 |
| 去掉 `CupertinoIcons.ttf` | 0.25 MB（压缩后 0.11 MB） | 中：是传递依赖，需确认无人引用 | 收益太小，暂不动 |

### 6.2 服务端缩略图方案（**需负责人决定**）

现状：`/media/public/:id` 直接发原图（商品图/分部图标可达 190KB 一张），
列表页一屏十几张图就是 1–2MB。

**不加依赖能做的（零风险，可先做）**：
- 客户端已用 `cacheWidth/cacheHeight` 做**解码尺寸**限制（省内存，不省流量）；
- 把长 TTL + `immutable` 下发（已做）→ 浏览器/代理层不再重复取；
- **管理端上传规范**：要求商品图 ≤ 200KB、尺寸 ≤ 1080px（纯流程约束，零代码）。

**真正做服务端缩略图 = 必须加依赖**（Node 没有内置图像处理）：
| 方案 | 许可证 | 说明 |
|---|---|---|
| `sharp`（libvips 绑定） | Apache-2.0 | 最快、内存可控，首选；需预编译二进制（Windows 有） |
| `@napi-rs/image` | MIT | Rust 实现，体积小 |
| `jimp` | MIT | 纯 JS，无原生依赖但慢、CPU 占用高 |

推荐 `sharp`（Apache-2.0，可商用、非传染性），做法：上传时生成 1–2 个规格
（列表 400px / 详情 1080px）落盘，`/media/public/:id?w=400` 选规格，
文件名仍是 uuid（继续满足 `immutable`）。**预计列表页图片流量降 70–85%。**

> 按硬约束"默认不加新依赖"：**本方案不实施，等负责人拍板**。

## 7 故障速查

| 症状 | 先查什么 |
|---|---|
| 全端"网络连接失败" | `curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:3100/api/v1/health`；再看 `pm2 logs fish-tunnel` 的当前域名是否与 `config/client-config.json` 一致 |
| 隧道域名变了 | 重跑 `scripts/publish-address.ps1`（无需发版） |
| ngrok 403 `ERR_NGROK_725` | 账号月度流量耗尽 → 等额度重置；期间客户端会自动切到 Cloudflare 隧道（`preferred` 探活失败即让位） |
| 用户报"连不上"，要定位 | 让他打开 **我的 → 设置 → 诊断 → 当前服务器地址**（截图即可：主机 + 来源 + 引导源 + 延迟 + 候选数 + 已切换次数） |
| 日志里看地址解析过程 | `adb logcat -s flutter \| findstr address`（`[address]` 前缀：引导源命中/失败、探活延迟、热切换） |
