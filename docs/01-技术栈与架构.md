# 01 - 技术栈与架构

## 技术栈（已确认）

| 层 | 选型 |
|---|---|
| 后端 | NestJS 11 + TypeORM 0.3 + TypeScript（Node 24） |
| 数据库 | MySQL 8.4（Docker，utf8mb4），Redis 7（Docker，AOF） |
| 实时通信 | Socket.IO（WebSocket 网关 /ws/chat） |
| API 文档 | Swagger（/api-docs） |
| 管理后台 | Vue3 + TypeScript + Vite + Naive UI |
| 客户端 | Flutter 3.47；boss-app / worker-app 两个工程共享 apps/packages/core（设计 token、API 客户端、模型） |
| 服务器 | Windows 11 本机（第一阶段），docker-compose 跑 MySQL/Redis，Node 直跑后端 |
| 穿透 | Cloudflare Tunnel（出站加密连接、自动 HTTPS） |

## 系统架构

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ 老板端 Flutter │  │ 工作端 Flutter │  │ 管理后台 Web  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │   HTTPS (Cloudflare Tunnel)       │
       └──────────────┬────────────────────┘
                      ▼
              ┌───────────────┐
              │  NestJS 后端    │  /api/v1 REST + /ws/chat Socket.IO
              │  - auth/RBAC   │  - 统一响应/异常/请求ID
              │  - wallet/order│  - 操作日志/登录日志
              │  - chat/leader │  - 限流
              └───┬───────┬───┘
                  ▼       ▼
          ┌──────────┐ ┌──────────┐
          │ MySQL 8.4 │ │ Redis 7  │   （Docker 容器，本机）
          │ 业务权威数据 │ │ 缓存/限流 │
          └──────────┘ └──────────┘
```

## 数据流要点

1. 客户端 → HTTPS（Cloudflare Tunnel）→ 本机后端 → 数据库。所有写操作的最终数据以数据库为准
2. 实时消息走 Socket.IO 长连接（连接认证后按会话房间收发），历史消息走 REST 分页拉取
3. 媒体文件存本机磁盘（第一阶段），元数据入库，通过 /media/public/:id 与 /media/protected/:id 鉴权访问（详见 docs/08）

## 后端模块划分（server/src/modules/）

| 模块 | 职责 |
|---|---|
| auth | 注册/登录/登出/refresh/me，JWT 签发与守卫 |
| rbac | 管理员角色、权限点、角色-权限关联 |
| user / worker / admin | 三端档案管理 |
| wallet | 积分钱包与流水 |
| game / category / product | 游戏、分类、商品及媒体 |
| order | 订单、状态机、价格快照、申诉 |
| chat | 会话、授权、消息（REST + WS 网关） |
| media | 统一媒体资源管理 |
| leaderboard / stat | 排行榜与统计 |
| setting / log / audit | 系统设置、操作日志、登录日志、安全审计 |
| schedule | 定时任务（派单超时、榜单汇总、备份提醒等） |

## 扩展性设计（新增游戏）

新增游戏原则上只通过管理后台操作：新增 game 记录 → 配置 game_config（段位/区服等游戏特有字段）→ 新增分类 → 新增商品。客户端按 game_config 的 JSON 配置动态渲染，不硬编码任何游戏业务逻辑（详见 docs/13）。

## 环境区分

- development / test / production 通过 NODE_ENV 区分；配置一律环境变量（server/.env、infra/.env），.env.example 为模板
- 迁移到云服务器时：docker-compose 与脚本保持模块化，仅替换连接配置，不修改代码（详见 docs/11）
