## 三、推荐方向与理由

**推荐方向 A（一卡多行）**：

1. **它才是"发丝线"的正确用法**。docs/21 明写「**列表用发丝线**」「**列表优先于卡片阵**」，而本页现状恰好是"把一张表单拆成卡片阵"。一张卡 + 卡内发丝线分行，把 5 个问题**一次**解决，且**不需要新增任何分组名**（后台只给 `label/placeholder/type/required/maxLength`，没有语义分组信息 —— 这是硬约束，两方向都没造分组标题）。
2. **与刚定案的「我的」页同族**。`site/design/profile-redesign/B.html` 已定案的视觉语言就是「卡片 + 卡内发丝线行 + 左标签右值」；下单页跟随它，全站才是一个语言 —— 否则就是负责人最忌讳的"一半精修一半原样"。
3. **省近 50% 垂直空间，且收益随字段数增长**。后台随时可加字段：3 → 9 字段下 A 省 51.7% → 49.2%（B 只有 13%~14%），越复杂的商品收益越大。
4. **圆角与卡片语言自动与相邻区块协调**。区服卡（`:319-336`）与护航员卡（`:364-385`）继续走 `_card`，自动继承「星号 11sp + radius 14 + 组间 20」，与信息卡同一节奏；价格卡（`:387-397`）与商品卡（`:463-520`）只吃"组间 20"这一个变化，不必重画。

**方向 B 的价值与边界**：改动面最小（`_card` 一处 + 循环微调），零结构风险；但省空间仅 15.5%，**问题 ③（碎片化）根因仍在**。如果负责人这一版只想"换皮不动骨架"，B 是安全选项。

**若两方向都不批**：最低限度建议先落 **B 的 `focusedBorder`（问题②）与错误文案（问题⑤）** —— 这两条是**功能可用性**问题（聚焦无反馈、报错找不到字段），不只是"好看"问题。

## 六、主动说明：「聚焦竖条」是否触红线？

**我们的判断：不触线**，理由逐条对齐 docs/21 原话（禁的是「**每张卡左侧一条彩色竖条**」）：

| docs/21 禁的形态 | 方向 A 的竖条 |
|---|---|
| **每张卡都有**（静态装饰） | **只有正在编辑 / 报错的那一行才有** |
| 固定不变 | **随聚焦与校验状态出现、消失**（120ms 过渡） |
| "彩色"（与业务无关的分色） | 只用 `--primary` / `--error` **两个语义色**，与标签同色 |
| 与内容无关 | 它是**交互反馈**（"光标在这一行"），删掉它聚焦就只剩颜色信号 |

**但如果负责人觉得"看起来像彩条"，三个替代方案任选（都不依赖颜色）**：

1. **替代 1（推荐兜底）**：删竖条，聚焦行改「**行底色 `#F8FAFD`** + 标签加粗转主色 + 输入行尾部 14dp 主色线性光标」—— 只靠**字重 + 底色**。
2. **替代 2**：竖条改为**行首 5dp 圆点**（聚焦 / 报错时才出现）。
3. **替代 3**：竖条**只保留给错误态**（错误必须有形状信号），聚焦态只用标签加粗 + 行底色。

三者都满足"**不能只靠颜色**"的要求（字重 / 图标 / 文案 / 底色至少两条同时在）。

## 七、三个必画状态（设计图里都有）

| 状态 | 落在哪一屏 | 表达方式（关键：**都不只靠颜色**） |
|---|---|---|
| ① **聚焦中**（哪个字段在编辑） | 屏 4（联系手机号）+ 屏 3（方向 B 对应形态） | A：行首 **2px 主色竖条 + 标签转主色并加粗**（形状 + 颜色 + 字重）；B：**主色描边 + 3px 柔光环 + 标签转主色** |
| ② **校验失败（2 个字段同时报错）** | 屏 4（备用联系方式 + 补充要求） | A：竖条转 error + 标签 `w700` 转 error + **输入框下方 11sp 中文文案**（前缀「此项必填，…」+ 后台文案后缀）+ **12dp 警示图标**（形状）；B：边框转 error + 标签转 error + 同一行文案 |
| ③ **长标签 / textarea 行内布局** | 屏 2（备用联系方式 maxLength 计数、补充要求 textarea）+ 屏 4（textarea 报错态） | 两档切换规则唯一：`label.characters.length > 4 \|\| type == 'textarea'` → **标签在上、输入在下**；≤4 字 → **左标签（固定 64dp）+ 右值**。**屏 4 同屏可见三档形态**（左右档 / 上下档 / textarea 上下档） |

**为什么阈值定在 4 字（本次出图时抓到的真风险）**：第一版稿按 6 字设阈值、标签列 56dp，设计图渲染后发现 **6 字标签在列内折行**（"游戏登录账 / 号"）。Flutter 中文实测 **12sp 每字约 12.2dp** → 64dp 一列正好容 4 字 + 必填星号，5 字就溢出。故最终定为：**≤4 字走左右档（64dp），>4 字或 textarea 走上下档**。这条必须写进实现（不是可选优化），否则真机上会出现标签折行。
