四、评审说明

现状问题（带行号）· 改造点（带行号）· 卡片三档 · 品牌元素 · 两状态差异 · 红线核对

1详情页现状 9 个问题（orders_page.dart，逐条带行号）

  • 它不是"页"，是一个弹层：:262-267 详情走 showModalBottomSheet（isScrollControlled），没有页头、没有返回、没有吸底操作；内容一长就把订单列表整页盖住，返回只能下滑手势。
  • 状态只有"颜色 + 文字"两条信号：:274-292 是「8dp 圆点 + 18sp 状态名」，圆点色取 :438-443 的 _statusColor() —— 9 个状态被压成 4 种颜色，taken 与 in_progress 同色、abnormal 与 after_sale 同色，无图标、无形状、无字重差异。
  • 没有状态时间线：全页没有任何"这一步什么时候发生的"。数据侧真因：GET /user/orders/:id（order.service.ts:1360）只回 {...orderView, gameZone, gamePlayerId, snapshot, settlement, workerInfo}，不下发 statusLogs；而同一张表 order_status_log 在管理端详情里是有的（order.service.ts:1496 / 1514）—— 老板端要画时间线，必须补这一处下发。
  • 价格没有算式：:319-322 金额卡只有「商品费用 + 订单数量」两行；单价在 :298-300 的另一张卡里（¥xx/单 × N），单价 / 数量 / 合计三行从不在一处，用户要自己乘一遍。
  • 七张卡长得一模一样：:373-386 的 _section 每块都走 AppCard（默认 radius: 16 + box-shadow，app_ui.dart:108 / 135-137）→ 服务信息 / 下单信息 / 护航员 / 金额 / 结算 同权重平铺，读不出"哪一块是重点"，违反 docs/32 §六「打破全是白圆角矩形」。
  • 护航员带冗余属性：:315 拼成「凌云（工号 W001）」—— 负责人口径是只有头像 + 名字；workerInfo 里的 workerNo 本就不该出现在老板端。
  • 全部行值同一档：:389-405 的 _kv 固定「96dp 标签 + 12.5sp 值」，商品名、区服、备注、金额、结算编号全用同一档；订单号在 :289 只有 10.5sp，被挤在状态行的右上角。
  • 操作按钮在内容流末尾：:347-348 把 _actionsFor(o) 排在所有卡片之后，长内容时必须滚到底才看得到；而 :680-700 里 taken / in_progress / canceled / abnormal 四个状态_ => [] 一个动作都不给（进行中的订单连"联系护航员"都没有）。
  • 完全没有加载态：:253-262 先 await 拉详情，成功后才 showModalBottomSheet —— 请求期间界面零反馈，点了订单卡像是没反应；失败只弹一条 toast（:355-358）。docs/21 §五 要求"必须设计加载态"。

  • :389-405 _kv → 分两档：行值 12.5 / 600、行键 11.5 / 400（现状同一档），行高统一 52。
  • 补加载骨架态（:253-262 现在完全没有）：骨架按真实区块的同一几何铺位，替代"点了没反应"。
