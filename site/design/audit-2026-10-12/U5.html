列宽靠注释维持，容易被后人改坏

"操作列固定 178px"「列宽和 = 984 → :scroll-x = 984」这类约定，全仓靠 34 处注释维护， 分布在 24 个页面。注释不会报错、不会被 vue-tsc 检查 —— 改了列宽忘改注释， 直到运行期才发现表格被裁。本图只出方案，不改代码。

// admin-web/src/utils/table.ts（新增：与 format.ts 同思路，口径单点） /** * 表格列宽口径（管理端唯一实现） * 目的：把"列宽和"从注释里搬进代码 —— 改了列宽，scroll-x 自动跟着变， * 不再依赖"记得同步改注释"。 */ /** 操作列宽度：按按钮数量分档（docs/14 的定宽列，写死一处） */ export const OP_COL_WIDTH = { one: 110, // 单个按钮（详情 / 处理） two: 178, // 两个按钮（处理 + 驳回）—— WithdrawView 用的就是这档 three: 250, // 三个按钮（编辑 + 下架 + 删除） } as const; /** 列宽和：从列定义里把 width 求和（minWidth 的弹性列不计入） */ export function sumColumnWidth(cols: Array<{ width?: number }>): number { return cols.reduce((s, c) => s + (c.width ?? 0), 0); } /** 建列时统一用它包一层：自动带 fixed:'right' + 统一宽度 + 统一渲染容器 */ export function opColumn<T>(opts: { width: number; // 用 OP_COL_WIDTH.two 这类常量，不写字面量 render: (row: T) => VNodeChild; }): TableColumn<T> { … }
// WithdrawView.vue（改后：列宽和由 sumColumnWidth 算出来，不再手写数字） const columns = [ …, const op = opColumn({ width: OP_COL_WIDTH.two, // 178 —— 单点定义 render: (r) => …, }); // 列宽和 = sumColumnWidth(columns) 自动得出，不写注释 ]; // 模板 <n-data-table :scroll-x="sumColumnWidth(columns)" … /> // 或者更省事：组件里直接不传 scroll-x，由 columns 推导（见"实现选项 B"）
✓ 关键变化：984 这个数字从两个地方消失（注释里一个、模板里一个）， 变成从列定义算出来。改任一列宽，scroll-x 自动跟随 —— 不再有"忘了同步"这个失败模式。

两种实现强度（建议先做 A）

选项 A 抽常量 + 求和函数（推荐先做）
做法新增 utils/table.ts：OP_COL_WIDTH 三档常量 + sumColumnWidth(cols)；逐页把 width: 178 改成 OP_COL_WIDTH.two、把 :scroll-x="984" 改成 :scroll-x="sumColumnWidth(columns)"。
收益操作列宽度全站一致；列宽和自动得出；新增页面照抄即可。
代价要动 24 个页面的列定义（机械替换，但面广）。
工时3–4 小时（含 table-actions 复跑）。
选项 B 再加静态检查（后续增强）
做法写一个脚本扫全部 views/*.vue：把列定义里的 width: 求和，与模板 :scroll-x 的值比对，不等即 FAIL；纳入提交前检查。
收益即使有人不按 A 的写法（仍手写字面量），也能在提交前发现不一致 —— 把"运行期才发现"提前到"静态检查就红"。
代价脚本要解析 .vue 里的 TS 对象字面量，有一定误报风险（条件列、minWidth、v-if 列）。
工时1–2 小时（可独立于 A 先做，作为 A 的过渡保护）。

逐项口径

项内容
现状「列宽和 = … → :scroll-x = …」全靠 34 处注释维护（24 个页面）；:scroll-x 共 64 处，值全是手写字面量；操作列宽度也是字面量（110 / 130 / 140 / 150 / 160 / 178 / 180 / 190 / 220 / 250 / 281 等十余种）。唯一例外是 UsersView.vue:276 的 USER_COLUMNS_WIDTH —— 但它同样是人手写的数字，只是从模板挪到了常量。
建议① 新增 admin-web/src/utils/table.ts，导出 OP_COL_WIDTH（操作列三档：one:110 / two:178 / three:250）与 sumColumnWidth(cols)；
② 逐页把操作列 width: <字面量> 换成对应档位常量，把 :scroll-x="<字面量>" 换成 :scroll-x="sumColumnWidth(columns)"；
③ 删掉那 34 处"列宽和"注释（信息已由代码表达，注释会过期）；
④ 可选增强：写静态检查脚本（扫 width: 求和 vs :scroll-x）纳入提交前检查。
影响面不需要动服务端。纯前端结构重构；不动接口、不动数据结构、不动列字段与渲染逻辑。
风险中等：列宽正是验收靶子（verify-admin-table-actions.mjs 量的是越界与折行）→ 改完必须复跑该套件（1280px 9 条记录应仍为 0 问题）。
建议分两步：先做选项 B 的静态检查（1–2h，零风险、立刻有保护），再做选项 A 的替换（3–4h）。
