# 08 - 媒体资源规范（统一媒体资源管理系统）

> 状态：**阶段 13 已完整落地**（media 模块 29/29 测试通过，含外网 Tunnel 取图验证；2026-09-21）

## 存储与命名

- 本地磁盘存储（第一阶段）：`MEDIA_ROOT/YYYY/MM/`（按日期分片），文件名 = 服务端生成 `UUID.ext`（stored_name），**绝不使用**客户端文件名
- 元数据入库 media 表（file_key/原文件名/类型/大小/尺寸/**sha256** 等；哈希用 sha256 替代 md5，同内容+同用途去重复用记录）
- 访问：`GET /media/public/:id`（公开，商品图/头像等）、`GET /api/v1/media/protected/:id`（认证 + 归属校验：聊天图片仅上传者/授权客服/管理员可读，防 IDOR）

### ⚠️ 两条通道的前缀**刻意不同**（2026-10-07 修正，踩过一次真故障）

`main.ts` 的 `app.setGlobalPrefix('api/v1')` **只排除**了 `media/public/(.*)`，所以：

| 通道 | 真实路径 | 谁生成 URL |
|---|---|---|
| 公开 | **根路径** `/media/public/:id`（无 `/api/v1`） | `MediaService.clientPath()` / 客户端按 mediaId 自拼 |
| 受保护 | **带前缀** `/api/v1/media/protected/:id` | `MediaService.clientPath()`（`isProtected=1` 分支） |

**故障复盘**：`clientPath()` 曾对受保护资源也返回根路径 `/media/protected/:id` → 实测 404
`Cannot GET /media/protected/201` → 充值审核的付款凭证图**永久转圈**。
当时的另一条候选修法（把 `media/protected/(.*)` 也加进 `exclude`）被否，因为
`admin-web/src/api/client.ts` 的 `protectedMediaUrl()` **早已**用绝对路径
`/api/v1/media/protected/${id}` 取图（线上可用）——加 exclude 会变成"新开一条平行路由 + 还要改管理端"。
**今后新增受保护媒体路由，一律挂在 `/api/v1/` 前缀下，并同步核对 `clientPath()`。**

补充（客户端侧，同一故障的第二半）：受保护图**必须带 `Authorization: Bearer <token>`**；
core 的 `CachedNetImage` / `ImageDiskCache` 走的是裸 `dart:io HttpClient`，**不会自动带登录态**，
调用方要显式传 `headers`（`proofImageHeaders(token)`）。带 headers 时磁盘缓存键按
"URL + 请求头指纹"分桶，避免换账号串图；公开图 headers 为空 → 键仍是 URL 本身（既有缓存不失效）。

## 上传校验清单（缺一不可）

1. **类型白名单**：jpg/jpeg/png/webp/gif（图片）、mp4（视频）
2. **MIME 校验**：与扩展名一致
3. **魔数校验**：读文件头验证真实类型（防改扩展名伪装）
4. **大小限制**（默认值，M2 前向负责人确认）：头像 2MB、背景图 5MB、商品图 10MB、商品视频 100MB、聊天图片 5MB
5. **内容检查**：图片重编码处理（剥离恶意负载），禁可执行类型
6. **文件名安全**：只保留扩展名做类型判断，存储名服务端生成
7. **路径安全**：文件 key 服务端拼接，杜绝 ../ 穿越
8. **md5 去重**：相同文件复用已有记录

## 图片处理

- 超过 1920px 等比缩放到 1920px；JPEG/WebP 质量 85 压缩（sharp，M2 引入）
- 记录宽高入 media 表

## 生命周期

- **替换**：更换头像/商品主图 = 新 media 记录 + 更新引用；旧资源延迟清理（定时任务，确认无引用后删除）
- **删除**：删除 media 记录时同步删文件；被引用的资源禁止删除（外键引用校验）
- 聊天图片长期保留（策略 M6 前向负责人确认）

## 客户端上传流程

1. 客户端调 `POST /media/upload`（multipart，带用途 type：avatar/bg/product/chat）
2. 服务端校验→落盘→入库→返回 mediaId
3. 业务接口只传 mediaId（如 PUT /user/profile {avatarMediaId}），服务端校验 media 存在且类型匹配
