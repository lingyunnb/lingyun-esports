| # | 事项 | 本批实现（默认） | 备选 |
|---|---|---|---|
| 1 | **邮箱码登录入口** | **`POST /auth/login` 增量**（传 `email`+`emailCode` 即走新路径，忽略 username/password） | 另开 `POST /auth/email/login` —— 接口语义更清楚，但客户端要改两处（URL + 返回处理） |
| 2 | **`role` 适用范围** | 绑邮箱接口 `/user/email/*` 放 `user`+`worker`；`POST /auth/qq/bind` 限 `user`；QQ 登录命中的账号必须 `role=user`；**`admin` 一律不放行**（因此 admin 拿不到邮箱码登录这条路） | 若希望管理端也能邮箱登录，需同时放开 `/user/email/bind` 的 admin 角色（**等于给最高权限面多开一条外部登录路径**，建议保持现状） |
| 3 | **邮箱码登录失败的状态码** | **400**「邮箱或验证码错误」（沿用既有"验证码失败 → 400"口径；401 在本系统的含义是"登录已失效，请重新登录"） | 401（与"账号或密码错误"对齐）——会让"登录页 401"同时被理解为"要重新登录" |
| 4 | **邮箱解绑** | **本轮不做**（邮箱已是登录凭据；开放解绑 = 开放"登录凭据被移除/被换走"） | ①只允许换绑（现状）②允许置空（需定义：置空后邮箱码登录立即失效、是否要再验一次码） |
| 5 | **`scene=register` 的枚举口子** | **保持既有行为**（邮箱已注册 → 明确 400「该邮箱已被注册…」）→ 因此"某邮箱是否已注册"本就公开可查；`bind` 场景据此也不做静默丢信 | 若要收紧，需把 register 场景也改成"静默返回成功"（**会改既有客户端文案与流程**，且 smtp 真发信下会给已注册邮箱白发一封） |
| 6 | **QQ 头像** | **不落库**（本站头像是 media 体系，`user` 表没有外链头像列；`figureurl_qq_*` 只随返回值带出） | 若要在 App 里显示 QQ 头像，需后端把图片转存为 media 再写 `user.avatar_media_id`（多一次下载+存储） |

**另需负责人提供**：QQ 互联应用的 **APP ID / APP Key**（`server/.env` 的 `QQ_APP_ID` / `QQ_APP_KEY`）。
未提供时接口一律中文 503「QQ 登录未配置」且**零网络调用**，服务端可先上线。
