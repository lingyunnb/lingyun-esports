# 13 - 游戏扩展配置规范（新增游戏零客户端改动）

## 目标

新增游戏原则上只通过管理后台完成：新增 game → 配置 game_config → 新增分类 → 新增商品。客户端不硬编码任何游戏的业务逻辑。

## 数据结构

| 层 | 表 | 说明 |
|---|---|---|
| 游戏 | game | code（如 codm）、名称、图标、banner、config_json |
| 游戏配置 | game_config | game_id + cfg_key → cfg_value JSON，游戏特有字段（段位/区服/模式等） |
| 分类 | category | 按游戏隔离 |
| 商品 | product | 归属游戏+分类；游戏特有属性进 extra_json |

## 客户端渲染规则

1. 首页：拉 `GET /public/games`（status 上架）→ 游戏列表；点游戏拉分类与商品
2. 游戏特有配置：拉 `GET /public/games/:code/config` 返回该游戏全部 game_config 键值；客户端按 key 驱动渲染（表单 schema 化：下单参数项由配置定义，选项由后台维护）
3. 商品 extra_json：下单页按 key 渲染扩展项（如 CODM 的"排位/匹配/大区"）
4. **客户端代码中禁止出现游戏名/段位/区服等业务字面量判断**

## CODM 接入清单（M2 种子数据）

- game: {code: codm, name: 使命召唤手游}
- game_config 示例：`{key: rank_list, value: [青铜,白银,...,传奇]}`、`{key: region_list, value: [微信区,QQ区]}`、`{key: mode_list, value: [排位赛,匹配赛,...]}`
- 分类示例：段位上分、代打、陪玩（具体由负责人确认）

## 验收口径（M2 起）

新增一个模拟游戏（测试数据）时：客户端零代码改动即可浏览其分类/商品/下单参数项。
