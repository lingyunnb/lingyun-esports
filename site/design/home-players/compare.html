货架装什么三个货架装陪玩（companion）：空态原文「暂无推荐陪玩」、类名 companion-*、商品字段 ×0我们这一版也把服务页货架改回装陪玩（上一版误做成商品货架，已作废）学负责人原话「选陪玩参考这个 app 的首页那里推荐」加「服务页主页不要放订单，要放打手介绍」——竞品首页货架就是陪玩货架，这是本次纠偏的核心依据
三货架结构（推荐 / 上新 / 热门）为您推荐 · 最近上新 · 热门点单（首页主体）沿用同名三货架，口径换成我们真实可查的：接单最多（completed_orders 降序）/ 新入驻（worker.created_at）/ 周榜前列（/public/leaderboard）学结构改口径三个名字业务上互不重叠、用户一看就懂；但它的口径在我们的接口里没有直接对应（没有 recommend 标记、没有上架时间下发），必须换成能验证的真实字段，否则就是编排序
纵向成列 · 一屏 1 到 2 条纵向成列，每条带封面纵向 ListCard 行（无圆角 + 发丝线），每条一张陪玩卡学列表优先于卡片阵（docs/21 第四节）；纵向行能承载「有人介绍长、有人介绍空」的真实现象

三个「必须由负责人拍板」的点

① 卡片底部那一行（已接 N 单 · 好评率）要不要？这会破结构规则 6
结构规则 6 当前只允许 头像 + 名字 + 介绍，且把「下单人数 / 评分」列为禁止项。竞品在卡片上放了这一行（.companion-meta），我们已有真实数据（接单次数、好评率）。
建议：单独批这一条，口径收窄到两个数（接单次数 + 好评率）且页面上只出现在这里（陪玩列表行与货架卡同一形态）。理由：店面上「这个人接过多少单」是老板决策的第一信息，比介绍更硬（介绍可以写得漂亮，接单次数不能）；不放的话，货架就只剩「名字 + 一句介绍」，用户无法区分谁更靠得住，货架三个口径（接单最多 / 新入驻 / 周榜）也就没有了视觉证据。
若负责人不批：本行整行删除即可（卡片高度从 124 变为 98），其余设计一字不动，退回规则 6 原始口径，零返工。
② 状态胶囊要不要？（空闲 / 忙碌）属于「需新增的数据能力」
竞品有（.companion-status：空闲 #ffad19 / 忙碌 #ff6c92 + 状态图）。我们的数据模型里完全没有这个字段。
最小实现代价（若要补）：① 服务端：打手态增加一次心跳或状态上报（复用 /worker/* 会话，写 worker_online_state(worker_id, state, updated_at)，state 取 可接单/忙碌/离线），或直接由「WS 是否在线 + 是否有进行中订单」派生（零新表，但语义是「在不在线」而不是「愿不愿接」）；② 管理端：打手档案页加一个可改状态的开关（1 个字段 + 1 个接口）；③ 客户端：货架卡的名字行右侧加胶囊 + 30s 轮询（或走 WS）。
估算：派生方案 1.0 人日（无新表，语义偏「在线」）；独立状态表方案 2.5 人日（语义准确，要碰打手态三屏）。建议先不做：状态过期（打手忘了改）会让老板看到假状态，比没有状态更糟。
③ 段位 / 颜值 / 服务之星三个徽章，建议明确不做
竞品四徽章的三个来源是 jdsta / isfwzx / isyzpw 三个字段（段位、服务之星、颜值）。段位是一个新的业务概念（要定义段位体系、要打手自证加官方审核、要管理端配置），颜值评定还涉及主观与合规风险。
建议：不引入，且不建「服不服」的临时字段。要体现「能力强」，可用的真实替代是接单次数与好评率（已在①）。
学习边界：只学「信息架构与信息密度」（首页装陪玩、纵向成列、头像加名字加介绍 2 行、一行元信息、每货架「查看更多」收敛到列表页、空态与到底文案位）， 不复制其图片素材、配色、圆角数值、徽章体系、状态语义与专属装饰（CLAUDE.md 方案 F/E 定案：照抄度高者作废）。 |事实来源（逐条可复核）：data/temp/tangzhou/app-view.js（scoped CSS 明文：.companion-name / .companion-desc / .companion-status / .companion-badges / .badge-img / .companion-meta / .list-state）、 app-service.js（转义解码后：空态「暂无推荐陪玩」×1、「没有更多了」×17、「空闲」状态枚举、shelfSections ×4、shelves 三货架）。 |我们的数据来源：/public/players、/public/workers/:id、/public/leaderboard、/divisions、/public/clubs、/public/banners（2026-10-15 本机实测）。 |本页为竞品结构还原，不含其任何图片素材（<img> = 0）。
