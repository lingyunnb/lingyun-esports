第 1 节 · v2 三套方案（3 套 × 5 状态）

每套 5 个状态：① 默认（有主图 + 有须知）② 长内容滚到底 ③ 无详情图/无封面（空态要好看） ④ 下单须知展开 ⑤ 底栏与内容的关系（最后一行不被压住，框上画了「底栏顶边 y=772」红线）。

A 服务卡式

主图位 = 自绘「护航流程三步」深底示意图 → 价格 + 标题同块 → 关键信息三列 → 提示条 → 平台保障条（托管结算 / 超时自动退 / 客服在线）→ 下单须知分段编号 → 商品说明。

  • 回答「这个服务分几步、谁来做、钱什么时候给」
  • 信息量最大，适合保底/上分类商品
  • 5 状态：默认 / 长内容 / 空态 / 须知展开 / 底栏关系
看 A 服务卡式 5 状态 →

B 极简克制 推荐

单图 16:9 走满宽 → 紧凑信息块（标题 → 价格 → 徽标 → 限购）→ 三列 → 下单须知默认折叠成一行 → 页脚。大量留白，最不像模板。

  • 第一屏只有 4 个信息块，浏览路径最短
  • 长条款默认不占版面，用户想看再展开
  • 空态是虚线 16:9 位 + 三个真实字段（不用插画填空）
看 B 极简克制 5 状态 →

C 双段式

上半「服务概览」= 服务流程示意 + 价格标题 + 三列；下半「下单须知 + 常见问题」， 两段用发丝线分段，FAQ 4 条可展开。

  • 把客服最常被问的 4 个问题前置，减工单
  • 章节标题左对齐 + 右侧灰字副标，靠排版而非彩色标签
  • 适合规则多、争议多的保底类商品

第 5 节 · 审批要点

推荐：B 极简克制（若负责人更看重「把服务讲清楚」则选 A）

理由：① 它是三套里最不像模板的一套——第一屏只有 4 个信息块， 没有卡片阵、没有缩略图条、没有装饰图标；② 下单须知默认折叠，把最长的条款从第一屏挪走， 直接解决 v1「首屏塞太满」的病根；③ 主图位是干净的 16:9，管理端后台上传真实商品图之后版面零改动； ④ 空态用虚线位 + 三个真实字段，不用插画填空，符合 docs/21。

若负责人的判断是「详情页必须一眼看懂卖什么、有平台背书」， 则选 A 服务卡式：它多了「护航流程三步」示意图与「平台保障条」三行，转化说服力更强， 代价是首屏信息量回到偏满。
