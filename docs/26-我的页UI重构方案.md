## 三、推荐稿与理由

### 3.1 推荐 **方案 B（卡片化收拢）**

推荐稿设计图：[recommended.html](../site/design/profile-redesign/recommended.html) · [recommended.png](../site/design/profile-redesign/recommended.png)
（= 方案 B 的细化，补齐 **深色版 2 张 / 未绑定态 / 空态** 共 7 屏）

**一句理由**：**它用最小的结构改动解决了现状最实的问题（6 张同权重卡片平铺、组内组外一样松），同时把页头那处被 docs/21 点名禁止的渐变主视觉一并去掉，且 0 处红线争议。**

**三条支撑理由（逐条可验证）**

1. **改的是真问题**。现状真正的毛病是**层级缺失**（9 条问题里 7 条属于此类），不是"内容顺序不对"。
   B 直接修层级：6 张卡 → 3 张主卡 + 卡内发丝线 + 卡间固定 22dp。
   A 解决"重点不突出"、C 解决"钱与单不够靠前"，两者都是**在层级没修好的前提下调顺序**，治标不治本。

2. **风险最低**。
   - A 要把资料头改成实色主色大色块（`:506-645` 整段重写，含背景图 / 头像 / 等级徽章 / 编辑按钮），改动面与回归面最大；
   - C 把三状态数字放大到 22sp 并置顶，**离 docs/21「禁顶部并排三个大数字」只差一步**，需负责人逐条确认口径；
   - B **0 处红线争议**，且页头形态与既有 `AppPageHeader`（`app_ui.dart:20-88`）同构，不是新发明。

3. **实现最省**。B 不需要任何新组件：`AppCard` / `AppHairline` / `AppSectionHeader` / `AppIcon` / `AppTag` / `AppIdentityTag` 全部现成
   （`app_ui.dart:103/91/285`、`app_icon.dart:18`、`identity_widgets.dart:235`），只改 `profile_page.dart` 一个文件 + 新增 1 个骨架占位组件。

### 3.2 方案 B 的一处口径说明（为什么卡内不是 8–10）

docs/21 写「组内紧（8–10）、组间松（20–24）」，指的是**组与组之间的间距节奏**。
B 的卡内是**行式列表**：行的可点区域必须 ≥44dp（触控标准），所以行内边距 13dp + 内容 30dp = 56dp 行高，
**行与行之间没有额外 margin（间距 0）**，靠 1px 发丝线分隔 —— 这比"8–10 的 gap"**更紧**，方向一致，不构成违反。
组间严格取 **22dp**，落在 20–24 区间内。

### 3.3 方案 B 的首屏可见内容（回答"首屏能看到什么"）

1. **页头**：白底 + 发丝线 + 19sp「我的」标题 + 右侧通知 / 设置两个线性图标；
2. **资料卡**：头像 52dp、昵称「阿远」、**当前身份：老板**、`ID: U 8471209365`、编辑资料，
   **同一张卡内**接会员成长（进阶会员 + L2 + 累计消费 ¥1,286.50 + 64% 进度条 + 「距精英会员还差 ¥713.50」）；
3. **资产卡**：余额 **¥248.60**（30sp 琥珀金）+ 全部订单 17 单 + 待接单 2 / 进行中 1 / 待评价 3 + 一行口径说明。

**首屏看不到**：服务卡 6 项、身份卡（切换身份 / 解除绑定）—— 滚动一屏即到（设计图用虚线标出折线位置）。

### 3.4 方案 C 的「并排三个大数字」口径（供负责人裁决）

docs/21 该条禁的是把「用户数 / 好评率 / 在线」这类**未经验证的填充指标**并排当 hero-metric。
方案 C 的三状态是**真实订单统计 + 可点动作入口**（点击进订单页对应筛选），且保持纵向"数字在上、名称在下"、
位于卡片内而非页头横幅 —— 按此理解**不构成违反**。但 C 确实把数字放大到了 22sp 并置顶，
是三个方案里最接近该红线的一版，故不作为推荐稿。**若负责人认为该条从严，C 可直接否决。**

### 4.1 关于深色档的重要说明（实施前提）

推荐稿已按任务要求出了 **2 张深色屏**（R-3 / R-4），逐值对照 `docs/14-UI设计规范.md`「管理端外壳」深色列
（底 `#0B1220` / 卡 `#111C2E` / 发丝线 `#1E2C42` / 正文 `#E8EEF7` / 次级 `#9DB0C8` / 三级 `#8CA3BE` /
主色文字态 `#7FB0FF` / 琥珀金 `#F0A63C`）—— 复用它是为了**三端同色系、不新增一套设计语言**。

**但必须如实说明**：老板端 Flutter 侧**当前没有深色 token，也没有主题开关**。
- `theme_tokens.dart` 只有 `kClassicTokens` / `kGlassTokens` 两份，**两份都是浅色**；
- `theme_mode.dart` 文件头注释写明「**用户可见的主题选择 UI 已全部移除**，2026-10-04 三端统一单一主题」；
- `settings_page.dart` 里已无任何主题相关代码。

**因此深色档若真要上线，是独立一轮**：在 core 新增一份深色 `ThemeTokens` + 恢复设置页主题入口 +
全端页面取色改走 `T` 门面（现状 `ThemeController` 仅 13 处引用）。**不应并进「我的页重构」。**
