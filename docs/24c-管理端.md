### F1 [已修] 安全审计页「整页连坐」：无 `admin:audit:read` 的账号连**有权看的登录日志**都拿不到

- **现象**：`operator` 角色（实测只有 `admin:log:read`，**没有** `admin:audit:read` / `admin:setting:read`）打开「操作日志与审计」页 → 三个请求塞在同一个 `Promise.all` 里，`/admin/logs/operations` 先 403 → **整体 reject** → 登录日志表格**一行数据都没有**，页面只剩一句红色报错。
- **证据**：
  - 前端 `AuditView.vue`（原 `L53-57`）：三个 `request()` 同处一个 `Promise.all`。
  - 服务端权限点**互不相同**：`log.controller.ts:30` = `admin:log:read`、`:46` = `admin:audit:read`、`system-status.controller.ts:21` = `admin:setting:read`。
  - DB 实测：`operator` = `admin:log:read` ✅ / `admin:audit:read` ❌ / `admin:setting:read` ❌。
- **根因**：**一个页面多个接口用同一个 try + Promise.all**，把三把不同的钥匙当成一把；任一 403 就整页失败。
- **修复**（`admin-web/src/views/AuditView.vue`）：三接口**各自判定权限、各自发请求、各自捕获**（无权限**不发请求**并就地中文说明）；系统状态卡无权限时不渲染；两表格分别给"需要 `admin:xxx` 权限点"提示；新增 `.perm-hint` 走 `--color-text-tertiary` token（**不硬编码颜色**）。
- **回归**：`vue-tsc` **0**、`build` **exit 0**。**哈希 `d4fa2d7`**

### F2 [已修] 订单详情「订单群组」字段名错 → 已接单订单被谎报成"未接单"（契约不一致）

### F3 [已修] 订单页三个动作按钮**一个权限点都没判**（权限渲染）

- **现象**：任何能打开订单页的账号，都会看到可点的「派单 / 撤销派单 / 取消」按钮。
- **证据**：
  - 前端 `OrdersView.vue`（原 `L237-245`）按**状态**渲染按钮，**无任何** `hasPermission`。
  - 服务端权限点：`order-admin.controller.ts:42` 取消 = `admin:order:cancel`、`:63` 强制完成 = `admin:order:write`、`:94` 派单 / `:113` 撤销派单 = `admin:order:dispatch`。

- **根因**：新增动作按钮时漏了权限判定（前端隐藏只是体验，但"该禁用的禁用/该隐藏的隐藏"是明确要求）。
- **修复**：加 `canDispatch` / `canCancel` 计算属性，按权限点渲染（详情只看 `admin:order:read`，不额外判）。
- **回归**：`vue-tsc` **0**、`build` **exit 0**；定向复验 `①` PASS（超管按钮全集正常）。**哈希 `486811c`**

### F6 [已修] 售后管理 / 聊天管理：分页状态齐全但**分页控件被关掉** → 第 1 页之后永远看不到

- **现象**：两页都从服务端**按页取数**（带 `page`/`pageSize`，把 `total` 存进 `ref`），但模板写死 `:pagination="false"` → **用户无法翻页**，超出第 1 页的记录**在 UI 上不可达**。
- **证据**：
  - `AppealsView.vue`：`const total = ref(0); const page = ref(1); const pageSize = 20;`（`L25-27`）、`total.value = data.total;`（`L38`）、请求带 `page`/`pageSize`（`L34`），但模板 `:pagination="false"`（原 `L112`）。
  - `ChatView.vue`：同构（`L40-42`、`L51`、`L48`），模板 `:pagination="false"`（原 `L143`）。
  - 服务端确实分页返回 `{list,total,page,pageSize}`。
- **根因**：分页控件被误关，`total`/`page` 成了**死状态**（"死代码"与"功能缺陷"同一处）。
