登录 / 注册页 · 三套方案对比

三套方案都在 390×844（iPhone 逻辑像素）下出图，每套 5 个状态：登录 / 注册 / 错误态·行内 / 错误态·顶部提示 / 键盘弹起。全部字段与流程逐条来自仓库盘点（下方「功能覆盖清单」）， 不存在的东西一律不出现：没有手机号 + 验证码、没有第三方登录、没有邀请码、没有独立注册页 / 闪屏页。 视觉硬约束逐条对照 docs/21-反AI味设计规范.md。

方案 A · 极简留白

大留白 + 单一主操作；输入框只留一条发丝下划线，无卡片、无阴影、无图标色块。

参考来源（项目 / 许可）

  • shadcn/ui 认证块（MIT）——表单即页面，标题 + 说明 + 字段纵向排列，不做容器
  • Refactoring UI（书籍，思路参考）——层级靠字号/灰度，不靠颜色块
  • Vercel / Linear 登录页范式——单一主色实心按钮，其余全为文字级操作

具体抄了什么

  • 字段纵向单列 + 分组间距（组内 10 / 组间 20）
  • 主按钮唯一实色，切换与找回降级为文字链接
  • 错误信息贴在字段下方，不用红色整框

优点

  • 改造成本最低：字段没变，只换视觉与间距；老板端/工作端同一版式即可
  • 最不容易出 AI 味（无渐变、无卡片阵、无阴影），长期耐看
  • 输入框纵向对齐一致，键盘弹起时布局不跳动

缺点 / 代价

  • 品牌识别弱：登录页与其他工具类 App 区分度低
  • 注册页字段一多（昵称 + 协议）就是一条长表单，缺少节奏
  • 协议勾选与「忘记密码」在极简风格里难安置（本稿用按钮下方一行处理）

对照 docs/21 反 AI 味规范

禁渐变做主视觉通过：全页零渐变，主色仅出现在主按钮与文字链接
禁每卡左侧彩色竖条通过：没有卡片
禁一律大圆角 ≥16通过：按钮 6 / 输入框 0（下划线）/ 勾选框 4；上限定在 6
禁阴影铺满通过：零阴影，仅 focus 时 3px 主色浅底圈
禁 emoji 当图标通过：仅 1 处 12px 行内错误图标（Material outlined 同体系路径）
组内紧 8-10 / 组间松 20-24通过：组内 10，组间 20

HTML： a-login.html · a-register.html · a-err-inline.html · a-err-top.html · a-keyboard.html

方案 B · 品牌主视觉

顶部一块实色主色品牌区（祁山标 + 品牌名 + 真实业务信息），表单以 14 圆角白卡压边接入。

参考来源（项目 / 许可）

  • Supabase Auth UI（Apache-2.0）——表单放进一张白卡，卡内只放字段与主操作
  • Material 3（Apache-2.0）——filled 输入框（浅底 + 圆角），聚焦时才描边
  • 国内手机号 + 验证码登录页的**信息层级**范式（只学层级与动线，不抄插画/吉祥物/文案）

具体抄了什么

  • filled 输入框（浅底 → focus 变白底 + 主色描边）
  • 主操作在卡底通栏，次操作降为卡内文字链接
  • 错误条放在卡内首行，滚动时随卡可见

优点

  • 品牌识别最强：一眼知道是祁连山电竞，且与 docs/19/21 的实色主色方向一致
  • 登录页承担了「3 个分部 / 客服时段」的真实信息，不是装饰
  • 注册页把协议放进卡片，结构与登录页共用一套骨架

缺点 / 代价

  • 品牌区占掉约 176px，小屏（<640 逻辑高）时表单会被压到折线以下
  • 实色大块对配色变化敏感，换主色时要重新验对比度
  • 比 A 多一点实现量：需要新增品牌头组件（约 1 个 widget）

对照 docs/21 反 AI 味规范

禁渐变做主视觉通过：品牌区是**纯实色** #2563EB，无渐变（docs/21 明确要求实色主色）
禁每卡左侧彩色竖条通过：无竖条，靠留白与圆角分隔
禁一律大圆角 ≥16通过：卡片 14 / 输入框 10 / 按钮 6 / 勾选 4
禁阴影铺满通过：全页零 box-shadow 投影，白卡压边用负 margin 叠色实现
禁装饰性插画通过：品牌区只有祁山标线稿（现有 AppQishanMark 逐值复刻）+ 两行真实数据
组内紧 8-10 / 组间松 20-24通过：组内 10，组间 20

HTML： b-login.html · b-register.html · b-err-inline.html · b-err-top.html · b-keyboard.html

方案 C · 卡片分区

把表单切成「账号 / 协议(或找回密码)」两段卡片，段标题带序号，顶部用分段控件切换登录↔注册。

参考来源（项目 / 许可）

  • Material 3（Apache-2.0）——分段按钮（segmented button）表达同页互斥状态
  • shadcn/ui Form + Card 结构（MIT）——字段成组、组有标题，错误落在组内
  • flutter_login（MIT）——登录/注册同一路由下的形态切换，注册只是多一段

具体抄了什么

  • 分段控件切换登录/注册（替代一行小字按钮）
  • 字段成组 + 组标题，错误定位到组
  • 卡内行与行之间用发丝线分隔

优点

  • 信息层级最清晰：每段只做一件事，注册多出来的「协议段」有明确归属
  • 表单类体验最好：错误落在所属分区，用户知道要改哪一段
  • 工作端差异最好表达（登录态只剩「账号」一段 + 找回密码说明段）

缺点 / 代价

  • 卡片数量多，视觉上比 A 重；段标题（账号/协议）有轻微冗余感
  • 分段控件 + 段标题 + 卡片三层结构，实现时组件最多（约 2-3 个新 widget）
  • 短屏时第二段容易被键盘遮挡，需要滚动

对照 docs/21 反 AI 味规范

禁渐变做主视觉通过：零渐变，主色只在选中段与主按钮
禁每卡左侧彩色竖条通过：段标题用 16px 圆形序号 + 文字，不是竖条
禁一律大圆角 ≥16通过：卡片 14 / 输入框 10 / 分段 6 / 段内圆 4
禁阴影铺满通过：零阴影，卡片一律 1px 发丝描边 #E5E9F0
禁每条信息配彩色小标签通过：段标题用灰度小字 + 序号，没有彩色标签
组内紧 8-10 / 组间松 20-24通过：组内 10，段间 18-20

HTML： c-login.html · c-register.html · c-err-inline.html · c-err-top.html · c-keyboard.html

两端差异（老板端 vs 工作端）

项老板端 boss-app工作端 worker-app设计稿如何覆盖
页面文件lib/pages/login_page.dart（登录 + 注册同页切换）lib/pages/login_page.dart（仅登录）同一套版式，工作端不出现「注册」入口
注册能力有：账号 + 密码 + 昵称（可选）无：账号由管理员创建分配工作端页脚文案「工作账号由管理员创建分配」（现网已有）
当前视觉液态玻璃 + 紫蓝渐变（#2B4BD7→#5B4BE0→#9B6EFF）原生 Material，主色 #2563EB，无卡片两端统一到本次定稿方案（工作端只取登录态）
错误呈现行内红字 + 汇总条 + AppToast（已整改）行内红字 + 汇总条，无 AppToast三套方案都画了「行内」与「顶部提示」两种

不一致点（需要负责人定）：老板端登录页仍是旧液态玻璃紫蓝渐变， 与全站青蓝 token（#2563EB / #06B6D4）不是一套；工作端是原生 Material 风格。也就是说现在两端登录页互不相同、且都与全站不一致。
