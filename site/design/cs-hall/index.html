有人申请客服 → 有客服权限的打手在打手态主动接

把现在「有人指派才有人管」的客服，改成像抢单大厅一样的待接入池：老板发起咨询 → 会话建出来（type='cs' / status='open' / 创建时无人指派）→ 有客服权限（worker.customer，与接单 take_order 完全独立）的打手在打手态看到并主动「接入」。

3接入后的会话页（客服视角）

沿用既有会话页版式（chat_v4.dart 硬参数），只有两处差异，另有一个待定能力。

位置老板视角（现状）客服视角（本稿）

退回池子—待定：虚线次级 + 待定标签，不与「结束」平级

接入那一刻，会话流里插一条系统消息「客服 老周 已接入」——老板和客服都看得到，谁接的、什么时候接的，可回溯。

4老板侧（对照）：还没人接的时候

修正现状的两句假话
  • 客服会话建出来就没有指派客服，但老板侧现在写死 「在线 · 刚回过」 与 「在线客服 · 平均 1 分钟回复」 —— 没人接入时两句都是假的，还承诺了时间。
  • 本稿改为：页头 「等待客服接入」（灰点）+ 系统消息 「咨询已提交，客服会尽快接入」，下面小字只给可验证的事实（在线时段 9:00–次日 2:00、高峰期会稍等、接入后有通知），不写几分钟内回。
  • 等待态不显示「结束咨询」（还没接入，结束没有意义），信息条状态也改成「等待接入」。
  • 老板在接入前发的消息不会丢，客服接入后能看到全部历史 —— 这一句也要让老板知道。

5反 AI 味自检（docs/21 第六节六条，逐条对本稿）

#自检问题本稿回答
1把内容换成任意同行的，这版设计是否还成立？不成立：页头「待接入 N · 在线客服 M」、等待时长琥珀阈值、老板昵称 + 咨询摘要的行结构，都只对"抢占式客服池"这件事成立。
2是否用了模型反射式的默认（渐变主视觉 / 卡片阵 / 全大圆角 / 满屏阴影）？无渐变（出图实测渐变面积 = 0）、无位图装饰、圆角只用 4/6/10/14/胶囊、阴影只出现在「退回池子」确认弹层这一处。
3把装饰全删掉，设计还剩下什么？剩下三件事：池子里有几条、每条等了多久、点哪个按钮接。图标只有耳机（客服）与时钟（等待）两个语义。
4每个颜色、圆角、间距能不能说出理由？能：主色 #2563EB 只给可操作（接入按钮 / 选中态）；琥珀 #D97706 只给"等太久了"这一个告警；圆角 6 给控件、14 给列表卡、胶囊给筛选；组内 8–10、组间 20–24。
5假数据是否具体、长短不一、有业务味？是：小北 / 陈默 / 夜航0831；摘要 单号 8241，开打前先跟我说一下、保 2 红单已经付好了，随时可以开；等待 2 / 6 / 13 分钟；工号 W20260073、在线时段 9:00–次日 2:00（非整数、长短不一）。
6空态 / 加载 / 错误态是否都设计了？空态、加载中各一屏；错误态不在本轮新增范围内（沿用既有页面既有实现，本稿不发明）。

6待拍板（我拿不准、需要负责人定的点）

  • 退回池子做不做：要做的话得先定三件事 —— 退回次数限制（防挑单）、退回后老板是否收到提示、退回是否计入客服考核。本稿只画了虚线次级样式 + 待定标签。
  • 「接入」要不要二次确认：抢占式 + 二次确认 = 抢不到；不做确认 = 误点就占了一条。倾向不做确认，靠"结束本次咨询"兜底。
  • 一个客服同时能接几条：本稿画的是"接一条就进会话"，没有任何上限提示。要不要上限（比如同时 3 条）？
  • 「在线客服 M」的口径：是"持客服权限且 App 在前台的心跳数"，还是"当前会话数 < 上限的人数"？在线时段 9:00–次日 2:00 之外怎么显示？
  • 等待时长 5 分钟的阈值：本稿按 >5 分钟转琥珀。要不要更早（3 分钟）？
  • 「本次咨询时长」从哪一刻算起：本稿按"接入那一刻"（chat_conversation_assign.created_at）。也可以按"老板发起那一刻"，两者对客服的考核含义不同。
  • 纯客服账号的「接单」要不要藏：这类账号点「接单」永远是空页。本稿保留（不动既有底栏），要不要对它只显示 3 项（接单 → 换成别的东西）？
