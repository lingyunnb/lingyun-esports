## 1. 一句话结论

**现状属于「半模板拼装」**：色彩 token 层（`AppColors`/`ThemeTokens`/`T` 门面）是**真的成体系**的，但**它下面没有品牌图形体系、上面没有组件体系**——三端各自漂移（Flutter 冰雪蓝 / admin-web 自造一套色 / 官网仍是旧紫蓝），于是整体观感停在"一个蓝底 + 一堆白色圆角矩形"。

**最缺的 3 块（排序）：**

1. **品牌图形语言（辅助图形 / 装饰体系）= 完全没有**——除了一个雪山 Logo，没有任何可复用的图形资产；全仓 `Image.asset` 使用数为 **0**，`CustomPainter` 只有 5 个文件、全是功能性绘制（2 枚"山"标 + 虚线边框 + 聊天气泡）。
2. **组件体系（三端共享的组件层）= 基本没有**——core 只有 10 个通用组件（`app_ui.dart`），admin-web 只有 **4 个**自建组件；页面全是就地手搓 `Container + BoxDecoration`（325 处），`BorderRadius.circular()` 出现 **23 种不同半径值**。
3. **字体层级（可执行的排版阶） = 不统一**——规范只有 5 级（22/18/15/13/12），代码里实际 **29 种字号 / 805 处**，峰值在 11.5sp（168 处）而规范里根本没有这一级；且工作端 `fontFamily: 'MiSans'` 指向一个**没有打进包**的字体。

#### 问题诊断

1. **token 层是好的，但只覆盖了约 85% 的用色点**：业务层仍有 **162 处（Dart）+ 140 处（Web）** 绕过 token；`level_style.dart`（30 处）与 `IdentityTone`（13 处）说明**"等级/身份"这两块最关键的状态色根本没进 token**。
2. **"一个品牌色"实际是四套色号**：Flutter / admin-web / 官网 / 工作端旧紫蓝（`fish_glass.dart:29-45`）——官网的 `#5B6CFF → #9B6EFF` 紫渐变 + `#E8C27A` 亮金**恰好是 docs/21 与 docs/14 明令禁止的方向**，却仍在线上。
3. **`docs/14` 已失效一半**：色板表整表过期，且与同文件 2026-10-11 新增的管理端章节自相矛盾。任何后来者按 `docs/14:11-21` 取色都会取到废弃色。
4. **语义色冗余**：24 个 token → 20 个值；"弱化文字"有 4 档、"浅蓝底"有 2 档且几乎同色。这不是"体系完备"，是**没人敢删历史 token**（app_colors.dart:36-39 的注释就承认了这一点）。

#### 升级建议方向（一句）

把 `docs/14:11-21` 换成本文档 §① 的 20 个现值作**唯一真源**，并把 `level_style.dart` / `IdentityTone` / `chat_v4` 私有三套色板**收编进 token**，同时为官网与工作端补一次色号对齐（或明确宣布官网/工作端不在升级范围）。

#### 判断：各个位置是否适合

| 用途 | 结论 | 理由 |
|---|---|---|
| **App 图标（启动器）** | ⚠️ **可用但偏弱** | 技术上完整（自适应 + 圆形 + 5 档密度 + 1024 前景全齐，安全区 66% 正确）。但**缩小到 48dp 时，"山体 + 雪帽 + 手柄 + 弧线 + 星芒"五层细节会糊成一团**；深墨蓝在小尺寸下几乎成黑块，远看是"一个黑三角"，与"专业、可靠、精致"有距离。另外**老板端与工作端图标只有一枚 24% 的「内」字之差**，安装后难以一眼区分（虽工作端已停用）。 |
| **首页（App 内）** | ❌ **不适合** | 位图 Logo 从未在 App 内使用（`Image.asset` 全仓 **0** 次）；首页品牌位实际由 `AppBrandHeader`/`AppMountainMark` 承担。源图带白色圆角底板 + 投影，直接放进页面会出现"白底白卡"叠白底。 |

| **商品卡片** | ❌ **不适合（且不该用）** | 商品卡需要"内容本身承担识别度"（`docs/29` §五第 2 条）；放一个七层细节的彩色 Logo 会与商品图抢注意力，且卡片尺寸下必然糊。现状**没有**这么做，是对的。 |
| **个人中心** | ❌ **不适合** | 现状个人中心用的是 `AppMountainMark`（单色线稿，15–20dp）与 `AppIdentityBar`，与位图的"彩色实心插画"风格**完全不同源**。位图 Logo 进去会破坏线稿一致性（docs/21 明禁装饰性插画）。 |

#### 问题诊断

1. **图标资产"齐但不精"**：形态细节太多、层数太厚，**没有做"小尺寸简化版"**（Android 只需要 48–192px 位图，源图 1254px 硬缩，没有 1 色/2 色的小尺寸变体）。
2. **同一品牌有三枚互不相干的标**（详见 ⑤ 与 §5）：位图雪山 Logo、`AppMountainMark`（双峰+雪顶线稿）、`AppQishanMark`（单峰+"祁"字部件线稿）——**形态、笔画数、视觉重量都不同**。
3. **品牌资产只为"App 图标"服务，没有任何"品牌页/物料"用图**：无横版 Logo、无反白版、无单色版、无安全边距规范、无最小尺寸规范。
4. **死资产两条 + 品牌断点一处**：`ic_launcher_foreground.xml` ×2（鱼形 F + 皇冠 / 蓝 F）零引用；`site/index.html` 的 logo 位是**文字 + 废弃紫渐变**。
5. **iOS 侧完全未换标**（默认 Flutter 蓝 F），admin-web 连 favicon 都没有——**"三端品牌一致"目前只做到 Android 两枚图标**。

#### 升级建议方向（一句）

保留"雪山 + 手柄"这一唯一记忆点但**重画为两档形态**（大尺寸保留层次 / 小尺寸只留 1–2 层轮廓），并补齐横版·反白·单色三套变体与 favicon/官网/桌面壳的换标。

1. **这是最重要的缺口，不是"次要欠缺"**：一个品牌的"精致度"几乎全靠辅助图形/纹理/留白节奏来承载。现在**除了 Logo 一笔都没有**，于是所有页面的"设计感"只能靠圆角 + 白卡堆叠——这正是负责人点名的"所有内容都是白色圆角矩形"的**根因**（详见 ⑥）。
2. **两套并存 : 老板端已经把光斑删干净，工作端还在跑旧紫粉光斑群**。工作端虽然"已废除、代码冻结"，但只要还有人打开旧版或跑回归，它就是**当前唯一还在渲染彩色光斑的地方**，也是"三端不一致"的最刺眼证据。
3. **官网的装饰方向与规范正面冲突**：`site/index.html` 的紫渐变标题、60px 蓝色 text-shadow、紫粉光斑，**逐条命中 `docs/21-反AI味设计规范.md` 与 `CLAUDE.md` 结构规则 5 的禁止清单**（渐变做主视觉 / 阴影铺满 / 装饰性光斑）。
4. **设计稿里已经画好的 16 个线性图标集（`site/design/add-friend/assets/icons/`）没有被产品化**——这是**现成可捡的资产**（见 §4）。

#### 升级建议方向（一句）

把"雪线的折角"抽象成唯一一套辅助图形母题（角/斜切/发丝线节奏），落地为 3–5 个可复用 SVG/Dart 装饰件 + 1 套 24 网格线性图标资产，然后**先把 `site/index.html` 与 worker `fish_glass.dart` 的旧紫粉装饰关掉**。

#### 问题诊断

1. **`AppCard` 的**默认值**就是问题本身**：白底 + 1px 描边 + 阴影 + **radius 16**（越档），配合 62 次使用 → 页面里出现的一切都长成同一个白圆角矩形。**没有"次要容器"档**（无边框卡、灰底卡、嵌入卡、分区带），于是层级只能靠间距表达，而间距只有 6 档（`app_spacing.dart:5-13`）。
2. **23 种圆角 / 11 个孤值 = 无分档**：`docs/21` 要求"圆角分档 4–6 / 10 / 14 / 胶囊"，实际最常用的是 **10（70）、6（56）、16（16）、14（31）**，其中 **16 与 12 都不在分档里**，而 `AppCard` 默认就是 16。
3. **缺的组件（按需求缺口列）：**
   - **无"卡片等级"体系**：只有一种 `AppCard`，没有 secondary/inset/plain 变体 → 这是"全是白卡"的直接机制。

#### 证据

- `docs/15-组件与动画规范.md:19` 规定「时长 **200~300ms**，缓动自然（ease-out 为主）」，`:21` 禁止「无限循环炫技动画」——但实测时长分布里 **>300ms 的有 25 处（400/500/600/800/900/1200/1400/1500/2000/2500/3500/8000ms）**，其中 **8000ms 1 处、3500ms 1 处、2500ms 1 处**（`worker-app/widgets/fish_glass.dart:31` 区间的旧光斑漂浮 + 骨架屏 1400ms 循环）。
- `Curves.easeOutBack` **6 处**——这是**回弹曲线**，与 `docs/15:21`「禁止过度弹跳」和 `docs/14:5`「禁止炫技动画」的方向相反（**需逐处确认是否属于 docs/15:20 允许的"成功反馈"**；未逐处判断，此处只报事实）。
- `Motion.emphasized` 与 `Motion.standard` 定义完全相同（`app_motion.dart:31` 与 `:33` 都是 `Cubic(0.2,0,0,1)`）→ 声称有两种曲线，实际一种。
- 全仓 65 处硬编码 `Duration(milliseconds: N)` 分布在 33 个文件，**说明命名常量形同虚设**：`AppDurations` / `Motion` 存在，但页面大量直接写字面量。

#### 问题诊断

1. **缺"时长令牌强制"**：3 套常量（`AppDurations` / `Motion` / CSS 变量）+ 25 种字面量值。同一动效语义（如"列表项入场"）在 `Motion.itemEnter=260` 与散落的 200/250 之间摇摆。
2. **缺"曲线语义表"**：4 种曲线，其中 `easeOutBack`（回弹）用了 6 次，与"克制"的品牌调性冲突；`emphasized`/`standard` 重复定义说明曲线名没有真实语义。
3. **动画覆盖面极窄**：核心场景没有动效——**无 `AnimatedList`（消息列表/订单列表无增量插入动画）、Hero 仅 1 处（商品图 → 详情的共享元素只做了一半）、无页面退出体系、无 tab 内容切换（老板端用 `AnimatedSwitcher` 淡入，工作端 `IndexedStack` 无过渡）**。
4. **无限循环 + 超长时长**：骨架屏 1400ms 无限 `repeat()`（属允许范围但无开关）、工作端光斑漂浮、`8000ms` 级别的一段动画——与 `docs/15:21` 的"禁止无限循环"需要对齐口径。
5. **`shimmer` 依赖声明但零使用**（`apps/boss-app/pubspec.yaml` 与 `apps/worker-app/pubspec.yaml` 都声明了 `shimmer: ^4.0.0`，代码 0 引用）——骨架屏是自己手写的 `FishSkeleton`，且只在老板端 1 处。
6. **admin-web 动效几乎为零**：只有 CSS 变量 150/200ms、侧栏过渡、欢迎序列；**没有加载/空态/列表的过渡**（配合 ⑥ 的 `n-skeleton` 0 次）。

#### 升级建议方向（一句）

把 25 种时长收敛成 3 档（120 / 200 / 300ms）+ 曲线只留 2 条（ease-out 进、ease-in 出），并把 `AppDurations` 与 `Motion` 合并成唯一出处。
