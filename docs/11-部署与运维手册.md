## 组成与端口

| MySQL 8.4 | Docker 容器 fish-mysql | 3306 |

## 公网地址与"重启不失联"（2026-10-04 落地）

**问题**：Cloudflare Quick Tunnel 每次重启都会换一个随机 `trycloudflare.com` 子域；地址过去被
`--dart-define` 烘进 APK → 电脑一重启，所有已安装 App 全部失联 → 每次都要重新打包发版。

**做法（地址动态下发 + 单一真相，零新增依赖）**：

| 角色 | 位置 | 说明 |
|---|---|---|
| 单一真相 | `config/client-config.json` | 由 `scripts/publish-address.ps1` 生成：`api` / `ws` / `candidates` / `updatedAt` / `source` |
| 固定引导地址 | `AppAddressResolver.bootstrapUrl`（`--dart-define=ADDRESS_BOOTSTRAP` 可覆盖） | 免费静态托管上的那份 JSON（当前指向 GitHub raw，**只读**，URL 永不变） |
| 客户端解析 | `apps/packages/core/lib/src/config/app_address.dart` | 拉引导 JSON → 多候选**并行探活取最快** → 写回 `AppConfigRuntime` → `AppConfig.apiBase/wsBase` |
| 兜底 | 编译期 `--dart-define=API_BASE_URL/WS_BASE_URL` | 下发失败/全部探活失败 → 用打包内置地址，App 一定起得来（最多阻塞 ≈3.5s） |
| 同源分发 | `site/client-config.json`（后端 `/site` 静态目录） | 与后端同源托管，**零后端改动**即得 `/site/client-config.json` |

**隧道地址变了怎么办**：跑 `powershell -File scripts/publish-address.ps1` → 它抓当前地址、写 JSON、
同步到 `site/`、做健康检查；再把同一份 JSON 覆盖到固定引导地址（人工一步，见脚本结尾提示）。
**App 不需要重新发版**。

**三处地址来源统一（单一真相）**：
- App：读下发地址（`AppConfig.apiBase` / `wsBase`），页面禁止写死地址
- 管理端：`/api/v1` 相对路径（同源，隧道换地址自动跟随）
- 官网 `site/`：`/api/v1/public` 相对路径（同源）+ `/site/client-config.json` 可被任何客户端读取

**为什么还要"固定地址"（负责人可选升级）**：动态下发让"换地址不用发版"，但仍需要一个固定引导 URL；
把 FISH 的公网入口本身换成**固定地址隧道/域名**（做法同 OtherProject 的 Sakura Frp：独立账号 + 独立隧道 ID +
独立端口，nssm 服务名 `FishTunnel`），则连"改下发文件"这步都可以省掉。两件事不冲突，建议都做。

**验证记录**：`vista-bind-archives-components.trycloudflare.com`（重发后当前地址）`/api/v1/health` = HTTP 200；
`/site/client-config.json` 公网可读且内容随 `publish-address.ps1` 变化（不需要动 App）。

## ngrok 固定域名方案（2026-10-04 上线，公网入口终于永久固定）

**为什么做**：Cloudflare Quick Tunnel 的 `*.trycloudflare.com` 每次重启都换随机子域 ——
即使有了动态下发（上一节），也还得"重启后改一次下发文件"。ngrok 免费档给 **1 个永久固定域名**，
把它当公网入口，连"改下发文件"这一步都省掉；App 侧一行不用改（地址本来就来自下发）。

### 凭据与文件位置（全部在 `infra/tunnel/`，**已被 `.gitignore` 忽略**）

| 文件 | 内容 | 说明 |
|---|---|---|
| `infra/tunnel/ngrok-token.txt` | ngrok authtoken | **绝不入 git**；脚本只读取并当参数传，从不回显（输出里掩码成 `3KE****…K9L`） |
| `infra/tunnel/ngrok-domain.txt` | 裸主机名，如 `<your-tunnel-domain>` | 不带 `https://`、不带尾斜杠；脚本会校验必须是静态域名 |
| `infra/tunnel/expected-games.json` | 三个游戏的中文名 + 代码（`peace` / `delta_mobile` / `delta_pc`） | 单独放 JSON 是因为脚本必须**纯 ASCII**（PS 5.1 GBK 解码坑，见上节） |
| `infra/tunnel/enable-ngrok.ps1` | 一键启用/校验/切换 | 幂等、支持 `-DryRun` / `-SkipSwitch` |
| `infra/tunnel/ngrok/ngrok.exe` | ngrok agent 3.39.11 | 本机自带，不入 git |

### 一键启用 / 回退

```powershell
# 启用（幂等：注册 token → 重启 pm2 应用 → 校验 → 写下发文件 → pm2 save）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\fish\infra\tunnel\enable-ngrok.ps1
# 只校验不切配置（推荐先跑这个）
... -File D:\fish\infra\tunnel\enable-ngrok.ps1 -SkipSwitch
... -File D:\fish\infra\tunnel\enable-ngrok.ps1 -DryRun      # 只打印命令，不落盘
# 回退（一行，apps 自动落到 Cloudflare 候选 / 打包内置地址）
pm2 delete fish-tunnel-ngrok && pm2 save
```

行为边界：**只**动 `fish-tunnel-ngrok`（ngrok）、`config/client-config.json`、`site/client-config.json`、pm2 进程列表；
**不碰** `fish-tunnel`（cloudflared 兜底保持 online）、**不碰** Windows 服务 `FishTunnel`（Sakura）、
**不碰**任何 `OtherProject-*` 容器/服务/端口。**校验不过就一个字节都不写**，并打印诊断（DNS / 本地后端 / pm2 状态 / ngrok 错误码）。

### 警示页跳过头（**必须**，否则探活是"假通过"）

ngrok 免费档对**浏览器式**请求先回一张插页：

```
HTTP 200   Content-Type: text/plain
You are about to visit <your-tunnel-domain>, served by 2409:8a7c:...
```

**状态码是 200** —— 所以"只看状态码"的探活会**假通过**，而正文根本不是 JSON（App 会静默回退内置地址）。
两道防线（脚本与 App 都做了）：

1. 请求头 `ngrok-skip-browser-warning: true`（ngrok 只判断"存在且非空"；**其它 host 一律忽略未知头**，所以无条件携带，不做 ngrok 专用分支）
2. **非浏览器 UA**：curl.exe 自带 `curl/8.x`；`Invoke-WebRequest` 显式 `-UserAgent 'fish-tunnel-check/1.0'`；
   Dart 侧 `HttpClient` 默认 `Dart/x.y (dart:io)` 本就不触发插页，代码里再显式写成 `FishApp/1.0 (Dart; dart:io)` 防回归

**再加一道更严的判据（光带头不够，头可能被中间层剥掉）**：断言响应体**能 JSON 解析**且含我们自己的特征 ——
`/health` 必须 `code=0` 且 `data.services.database` / `data.services.redis` 存在；
`/public/games` 必须同时命中三个**游戏名**与三个**游戏代码**（代码来自游戏表，插页编不出来）。
App 的探活同理：`AppAddressResolver.fetchHealth` 现在 **HTTP 200 之外还要 `isHealthBody` 通过**，
插页候选会被直接淘汰（而不是"选到一个警告页地址"）。

### 免费档限制（如实记录）

| 限制 | 影响 | 我们的处置 |
|---|---|---|
| 1 个静态域名 | 只能一个入口 | 够用；`candidates` 里同时留 Cloudflare 兜底 |
| 浏览器插页 | 见上 | 请求头 + 非浏览器 UA + 正文契约断言 |
| 带宽/连接数有限（免费档共享） | 高并发下可能被限速 | 内测规模够用；真放量需换付费档或云服务器 |
| 会话/请求日志有留存限制 | 排查只能靠 ngrok inspector `http://127.0.0.1:4040` | 出问题先看 inspector + `pm2 logs fish-tunnel-ngrok` |
| 域名不是自己的（ngrok 子域） | 换服务商要改下发文件 | 地址来自下发，App 无需发版 |

### 切换后的地址状态（2026-10-04）

```

  candidates = [ ngrok …/api/v1 , https://vista-bind-archives-components.trycloudflare.com/api/v1 ]  ← 备

```

- **冷启动双轨**：引导地址（GitHub raw，可能不可达）拿不到时，可直接从固定域名取
