# 21 - 反 AI 味设计规范（去"机器感"清单）

> 负责人 2026-10-03 要求："设计不要 AI 化，要让用户一眼看过去就像真人设计的"。
> 依据（均为公开专业资料）：
> - [AI Slop Patterns Reference](https://github.com/borghei/Claude-Skills/blob/HEAD/engineering/design-auditor/references/ai_slop_patterns.md)（AI 生成 UI 的通用特征与整改方法）
> - [AI Design Slop: the visual tells to refuse](https://github.com/manusco/wolfgang/blob/main/.agents/skills/design/designer/references/ai_design_slop.md)（视觉/交互层面的"机器味"清单）
> - [Refactoring UI](https://refactoringui.com/)（层级、间距、色彩、阴影的工程化做法）
> - [Why Most AI-Generated Designs Look the Same](https://www.vandelaydesign.com/why-ai-generated-designs-look-the-same/)
>
> **本清单是 UI 验收依据：每版设计稿与实现都要逐条自检。**
>
> **适用范围（2026-10-11 补充）**：本清单的禁止项主要约束**老板端与一切对外界面**——那才是"用户一眼看过去像不像真人设计"的战场。
> **管理端（admin-web）是内部工具**，**允许更密的表格与更功能化的密度**（列更多、字号更小、一屏放更多字段、页签常驻）：内部用户要的是"一屏看完、少点两下"，不是"好看"。
> 但**三条底线对管理端同样生效**：**禁 emoji 当图标、禁装饰性插画、禁无理由渐变**（"内部工具"不是放飞的理由）。
> 管理端外壳的具体口径（主题色值 / 侧栏分组 / 登录页 / 欢迎语）见 `docs/14-UI设计规范.md`「管理端外壳（2026-10-11 定案）」。

## 一、为什么会"一眼 AI"（原理）

模型在同一批训练样本上收敛 → 产出的是**统计中位数**：紫色/蓝色渐变、三列卡片、全部大圆角、随处可见的阴影、居中排布、泛泛的 CTA 文案。
**AI 味的本质不是"好看/难看"，而是"每个选择都没有理由"。** 所以整改方向是：**给每个视觉决策一个业务理由**。

## 二、视觉层：禁止清单（我踩过的雷已标注）

| 禁止 | 为什么 | 正确做法 | 本项目状态 |
|---|---|---|---|
| **渐变当主视觉**（紫→蓝、青→蓝按钮/横幅） | 是 AI 默认反射，且与品牌无关 | 主色用**实色**；渐变只做极小的装饰面积或不用 | ✅ 已改：按钮/浮标/横幅全部实色蓝 |
| **每张卡左侧一条彩色竖条** | 被明确点名为"过时模板签名" | 用**结构分区 + 排版层级**表达分组 | ✅ 已删（首版方案 F 有） |
| **全部元素大圆角（≥16）** | 玩具感、软塌，无层级 | **圆角分档**：小控件 4–6 / 卡片 10 / 弹层 14 / 胶囊全圆 | ✅ 已改（6/8/10/14 + 胶囊） |
| **阴影铺满所有卡片** | 超过一半容器带阴影即"模板感" | 列表与卡片用**发丝线**；阴影**只给弹层/悬浮层** | ✅ 已改（只弹层有阴影） |
| **顶部并排三个大数字**（用户数/好评率/在线） | 典型的"hero-metric 模板"，未经验证=填充物 | 换成**真实业务信息**（高峰时段、平均接单时长、今日单量） | ✅ 已改 |
| **每条信息配一个彩色小标签** | 靠彩色小片堆砌层级=模板感 | **标签只给必须区分的项**（平台/状态/价格）；主次靠字号字重与灰度 | ✅ 已改 |
| **居中对称、处处均匀间距** | 破坏阅读边、无节奏 | **左对齐为主**；**组内紧（8–10）、组间松（20–24）** | ✅ 已改 |
| **emoji 当图标** | 字体依赖、不专业、跨设备不一致 | **统一线性图标库**（`lucide_icons`，同一描边同一语义，不混实心） | ✅ 设计稿已统一线性 |
| **玻璃拟态/光斑/装饰插画** | 无功能理由的模糊与装饰 | 只在**确实需要层级**时用（如导航磨砂）；装饰一律删 | ✅ 已停用液态玻璃主题 |
| **纯黑配纯白** | 对比过硬、刺眼 | 近黑 `#0B1220` + 冷灰底 `#F5F7FA` | ✅ 已改 |
| **假数据（4.9 / 3589 / 50000 这种整数）** | 一眼假，是最强"机器味"信号 | **拟真**：非整数、长短不一、带具体场景（`2,847 单`、`9:00-次日 2:00`、`不接急单`） | ✅ 已改 |

## 三、内容层：文案与数据

| 禁止 | 正确做法 |
|---|---|
| 泛泛 CTA：「立即体验」「了解更多」「一键开启」 | 说清**动作与结果**：「快速下单」「去接单」「查看战绩」 |
| 营销空话：极致、赋能、一站式、畅享 | **具体可验证**：「平均 3 分钟内接单」「客服 9:00-次日 2:00 在线」 |
| 每段字数一样长（明显占位感） | 长短交错，像真人填的内容 |
| 编造的装饰数据 | 只展示系统真实产生的数据；没有就留空态 |

## 四、结构层

- **顺序按业务需要，不按模板**：我们的顺序 = 选分部 → 看官方自营 → 下单；不是 Hero→特性→推荐→定价→页脚
- **同一入口只出现一次**：底部导航已有的，顶部不再出现（详见 CLAUDE.md 结构规则）
- **卡片形态允许不同**：分部用列表、陪玩用纯文本流、榜单用表格行、帖子用内容卡 —— 不要"什么内容都塞进一样的圆角卡"
- **列表优先于卡片阵**：能用列表 + 发丝线说清的，不要拆成一堆卡片

## 五、交互层

- 状态要有过渡（不 0ms 硬切），但**不做炫技动效**
- **必须设计空态 / 加载态 / 错误态**（只有 happy path = 真实使用时会像坏了）
- 空态给**下一步动作**（如"完成第 1 单后进入榜单"）

## 六、验收自检（每次出图/提交前逐条问）

1. 把内容换成任意同行的，这版设计是否还成立？（成立=太通用）
2. 是否用了模型反射式的默认（渐变主视觉 / 卡片阵 / 全大圆角 / 满屏阴影）？
3. 把装饰全删掉，设计还剩下什么？（剩不下=装饰代替了结构）
4. 每个颜色、每个圆角、每个间距，能不能说出理由？
5. 假数据是否具体、长短不一、有业务味？
6. 空态/加载/错误态是否都设计了？

## 七、当前"找陪玩"页的合规示例

负责人要求：**只显示陪玩名字 + 介绍（介绍由管理端填写），其余一律不要**。实现：

- 列表：`名字（14.5 粗）` + `介绍（12 号，1–3 行，长度自然不一）` + 发丝线分隔
- 页头一行小字说明来源：「介绍由官方审核填写」
- 底部一行「快速下单」浮标（唯一动作）
- **不要**：头像、价格、评分、状态标、等级、标签、下单人数、语音时长 —— 这些一律不进列表（需要时进详情页）
