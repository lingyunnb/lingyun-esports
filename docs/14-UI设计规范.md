# 14 - UI 设计规范（三端统一）

## 设计方向

白色、简洁、现代、轻量、高级、有艺术感。**禁止**：荧光色、黑红电竞风、霓虹灯、夸张渐变、大量粒子、炫光、复杂背景、无意义装饰、堆砌卡片、炫技动画。艺术感来自比例、留白、字体、层级、细节、交互，而非装饰。

## 页面设计检查清单（每个页面过一遍）

1. 用户第一眼看到什么？（最重要的信息/动作）
2. 用户下一步应该做什么？（主操作是否明显）
3. 重要信息在哪里？（积分余额可见但不喧宾夺主；订单状态一眼看懂）
4. 按钮是否容易找到？
5. 状态是否容易理解？
6. 页面是否拥挤/过于空？
7. 视觉是否与全站统一？

## 入口唯一性（结构规则 1 的注解）

**快捷面板是快捷方式，不计入「同一入口只出现一次」的判定。**

- 「同一入口只出现一次」约束的是**导航层**（底部导航 / 顶部导航 / 页面主体的可见入口）——
  同一个功能不能在两处导航层各挂一次（如底部已有「消息」则顶部不再出现「消息」）。
- **快捷面板**（长按底栏中间凸起按钮弹出的 `AppQuickActionsSheet`）是**去别处也能做到的事的捷径**，
  它不构成第二个"入口层"：用户不看面板也能通过正常路径到达同一功能。
- 但它**有一条硬边界**：面板里**不得放"正常路径上已经不存在"的功能** ——
  那等于把唯一入口藏进一个隐藏手势（2026-10-15 的「找陪玩」就是先例：
  面板项与顶部导航项**必须在同一次提交内**一增一减，否则用户要么彻底找不到入口，要么同一入口出现两次）。

## 各端设计优先级

- 老板端：下单按钮突出但不破坏平衡；商品图片比例统一（建议 4:3 或 1:1）；订单状态色点+文字
- 工作端：接单/查看/处理订单效率优先；大厅列表信息密度高、动作明确
- 管理后台：信息密度、操作效率、数据可读性优先；表格为主、操作留痕提示
- 聊天页：消息阅读与输入体验优先
- 个性化（头像/ID/昵称/背景图）真正融入个人主页，不单独塞设置页

## 主题系统（2026-09-22，仅老板端）

- 两套主题：**初始主题**（classic，默认，与既有视觉完全一致）/ **液态玻璃**（liquidGlass：半透明玻璃表面+边缘高光+背景光晕+悬浮玻璃导航，克制不炫技）
- 架构（core 包）：`AppThemeMode` 枚举 → `ThemeTokens`（颜色/圆角/玻璃参数）→ `ThemeController`（全局控制器，**按账号持久化**，重开保持）→ `T` 门面取色 → `GlassSurface`（统一表面）/ `GlassBackdrop`（环境光晕）/ `buildGlassTheme()`（Material 组件玻璃化）
- 规则：页面取色走 `T` 门面或 GlassSurface，禁止硬编码主题色；新主题=新增一组 Token+ThemeData，不重写页面
- 性能守卫：列表内玻璃表面默认不开 BackdropFilter（纯半透明填充）；模糊只用于导航/弹窗/背景层；背景光斑仅两团低速漂浮
- 工作端/管理端不接入主题系统

## 品牌视觉（2026-10-03 更名为祁连山电竞）

- 品牌名：**祁连山电竞**（老板端 App 名 / 官网 / 管理端）；工作端 App 名 **祁连山电竞内部**
- 品牌色：沿用主色 `#5B6CFF` 体系不变；**图标**以祁连山雪山为核心意象（暖金晨光=老板端、冷蓝夜色=工作端）
- 图标资产（双端一致结构）：
  - 传统：`mipmap-*/ic_launcher.png`（圆角方形）、`ic_launcher_round.png`（圆形，旧设备）
  - 自适应（Android 8+）：`mipmap-anydpi-v26/ic_launcher.xml` = 前景位图 `drawable/ic_launcher_foreground_src.png`（内容 66% 居中含安全区）+ 背景色 `values/ic_launcher_background_color.xml`
  - 启动图：`drawable/launch_background.xml`（品牌背景色 + 图标居中）
- 生成方式：`scripts/tmp/make-icons.py`（Pillow，素材 `scripts/tmp/brand/src1.jpg` = 雪山摄影，Pexels 免费素材）；改图标后**必须重跑并重新发布双端**（图标进包，不能云更新单独替换）
- 内部标识不动：Dart 包名 `fish_core`、组件 `FishGlass*`、Android 包名 `com.fish.*`（改名成本高且用户不可见）

## 管理端外壳（2026-10-11 定案）

> 本节是**既成事实的回写**：管理端（`admin-web`）外壳已按 2026-10-11 两轮改造落地并**逐项实测验收**（收口提交 `bea8bd3`），
> 本节只记录**已实现**的口径，不是新方案；**老板端既有条款一条未动**。
> 定位：管理端走**浅色科技风**——与老板端「冰雪蓝 + 冷灰蓝底」**同一主色体系**，但更偏**工具化、密度更高**（表格为主、信息密度优先，见上文「各端设计优先级」）。
>
> ⚠️ 与上文 2026-09-22「工作端/管理端不接入主题系统」不冲突：那条说的是 Flutter 端那套「初始主题 / 液态玻璃」；
> 管理端 2026-10-11 起有**自己的**浅/深双档 CSS 变量（`html[data-theme]`），两者不是同一套东西。

### 1. 主题：浅色为默认（深色档保留在右上角可切）

| 用途 | 浅色档（**默认**） | 深色档（右上角可切） |
|---|---|---|
| 页面底 | `#F5F7FB`（冷灰蓝） | `#0B1220` |
| 卡片 / 表面 | `#FFFFFF` | `#111C2E` |
| 发丝线 | `#E5E9F2` | `#1E2C42` |
| 正文 | `#1F2937` | `#E8EEF7` |
| 次级文字 | `#5B6B82` | `#9DB0C8` |
| 三级文字 | `#5E7085` | `#8CA3BE` |
| 主色 | **冰雪蓝 `#2563EB`** | 同色（**文字态**提亮为 `#7FB0FF`） |
| 点缀色 | **青 `#06B6D4`** | 同色 |
| 琥珀金（金额/等级） | `#B45309` | `#F0A63C` |
| 表格发丝线 | `#DCE3EE` | `#26364F` |

- **同一批 CSS 变量翻转**：`html[data-theme]` 驱动（`admin-web/src/styles/tokens.css`）；Naive UI 侧另有深浅两套 `GlobalThemeOverrides`（`admin-web/src/theme.ts`）；主题偏好落 localStorage，**默认浅色**。
- **侧栏浅色档也是白底**（`#FFFFFF`），用 **1px 发丝线 `#E5E9F2`** 与主区分隔；深色档侧栏近黑 `#0B1220`。
- 深色档不删：右上角明暗切换随时可切回，两档共用同一套变量名（页面不得写死主题色）。
- 深色档的对比度收口口径：`--color-primary` 在深色档**重映射**到提亮后的 `--color-primary-text`（`#7FB0FF`），装饰色块另走恒定的 `--brand-primary`——为的是"主色当文字用"（选中项、金额、链接）时对比度达标。浅色档主色当文字用沿用 `#2563EB`。

### 2. 侧栏：分组折叠（8 个顶层项）

| # | 顶层项 | 类型 | 子项（路由名 · 权限点） |
|---|---|---|---|
| 1 | **工作台** | 直接项 | `dashboard`（无权限点，恒可见） |
| 2 | **订单与售后** | 可折叠（5） | `orders`·`admin:order:read` / `appeals`·`admin:appeal:handle` / `refunds`·`admin:refund:read` / `complaints`·`admin:complaint:read` / `tips`·`admin:tip:read` |
| 3 | **用户与身份** | 可折叠（3） | `users`·`admin:user:read` / `identity-bindings`·`admin:user:read` / `workers`·`admin:worker:read` |
| 4 | **资金与抽成** | 可折叠（3） | `wallets`·`admin:wallet:read` / `recharge`·`admin:setting:read` / `commission`·`admin:order:read` |
| 5 | **商品与内容** | 可折叠（7） | `catalog`·`admin:product:write` / `divisions`·`admin:division:read` / `clubs`·`admin:club:read` / `order-form`·`admin:setting:read` / `announcements`·`admin:home:write` / `banners`·`admin:home:write` / `site-manage`·`admin:site:edit` |
| 6 | **客服与消息** | 可折叠（2） | `chat`·`admin:chat:read` / `feedback`·`admin:feedback:read` |
| 7 | **排行榜** | 直接项 | `leaderboard`·`admin:leaderboard:read` |
| 8 | **系统管理** | 可折叠（4） | `settings`·`admin:setting:read` / `admins`·`admin:admin:read` / `audit`·`admin:audit:read` / `app-update`·`admin:app:write` |

合计 **2 个直接项 + 6 个可折叠父项 = 8** 个顶层项；**子项 24 + 直接项 2 = 26 条导航**，覆盖除 `/login` 外的**全部 26 个页面路由**（一个页面没漏）。

**交互规则（逐条）**

- **父项是真 `<button>`**（带 `data-nav-group`，便于验收脚本断言）+ 右侧 chevron；**展开时 chevron 旋转 90°**，点击就地切换展开 / 收起。
- **进入某页自动展开其所在组**：`watch(route.name, { immediate: true })`——首次直接访问 `/orders`（没有 sessionStorage）也要展开「订单与售后」，不靠用户去点。**允许同时展开多组**（刻意不做手风琴、不自动收起其它组）。
- **展开态落 `sessionStorage`**（键 `fish_admin_nav_expanded`）：它是"这次办事要看哪几组"的**过程状态**，不是长期偏好——新开窗口应回到「默认 + 当前路由所在组」。没存过时默认展开**前 3 个可折叠分组**（订单与售后 / 用户与身份 / 资金与抽成），当前路由所在组恒兜底展开。
- **折叠态（64px 图标条）点父项 = 先展开侧栏、再展开该组**（一次点击就能看到子项，不存在"点不到的子项"）。
  **刻意不做浮层弹出菜单**：浮层在 `overflow:hidden` 的侧栏里要 teleport、要自己管定位与"点击外部关闭"，多出一整套状态；而"点一下先展开侧栏"对管理端就是一次点击、零额外状态。理由已写在代码注释里（`LayoutView.vue` 文件头）。
- **选中态 = 浅底 + 主色字 + 左侧 3px 主色条**（浅底 `rgba(37,99,235,.07)`、主色字 `#2563EB`、条宽 3px 圆角 `0 3px 3px 0`）。**父项与子项同一套规则**（父项高亮 = 该组内含当前页），视觉上是**一根连续的层级线**；只给父项加条会让长列表里"到底选的是哪一项"变模糊。折叠态没有 3px 条的空间，改用整块淡蓝底表达当前项。
- **权限联动**：子项的权限点与标签**逐条沿用改版前的 `menuOptions`**（一个权限点没换、一个页面没漏）；**父项自身不带权限点**，其子项按同一个 `hasPermission` 过滤，**子项全不可见 → 父项整体隐藏**（不渲染空组）。
- 侧栏宽度 **220 ↔ 64** 折叠（落 localStorage），宽度与展开态均有 200ms 过渡；菜单容器自带纵向滚动（分组展开后条目会超过一屏）。

### 3. 登录页：居中白卡

- 构成 = **淡灰底 + 极细网格 + 一处淡品牌色光晕 + 正中白卡**（纯 CSS，**无任何图片**）：
  - 底色 `#F5F7FB`（与主区同一档冷灰蓝）；
  - 极细网格：两条 1px `linear-gradient` 平铺，**40px 一格**；浅底上用**正文色的 4%**（`rgba(31,41,55,.045)`，白线在浅底上等于没画）；
  - 一处品牌色柔光晕：`radial-gradient`，冰雪蓝 10% → 青 6% → 透明（**一处**，不是"光斑群发"）；
  - **居中白卡 400px**：圆角 14、`1px #E5E9F2` 发丝描边 + 一层极轻外投影（不铺阴影）；卡顶 **3px 品牌色条**（冰雪蓝 → 青，**全页唯一一处渐变且只有 3px 高**）+ 雪山标 + 账号 / 密码 / 登录 + 一行页脚说明。
- **明确不采用「左大图 + 右登录卡」布局**——理由：**负责人要求避免与外部参考视频雷同**（该构图是参考视频的标志性画面，照搬等于"一眼看着像抄"）；居中白卡同样能承载"品牌 + 两个输入 + 一个主按钮"，且不与外部素材产生联想。
- **不使用任何第三方插画 / 网图 / 视频截图**：品牌标只用**本仓库自己的素材**（复刻自 Flutter core 的 `AppMountainMark`），背景只有 CSS 网格与光晕。
- 登录流程一行未改（仍 `/auth/login` + `role=admin` + 单设备顶号 `?reason=`），改的只是模板与样式。

### 4. 登录成功欢迎序列

- **文案唯一出处**：`admin-web/src/constants/welcome.ts`——页面里**不许内联任何一句欢迎文案**，以后改字只改这一处（逐字照用，不改字、不改标点）。
- **角色区分**：
  - `is_owner=1`（董事长 / 所有者）→ **两行**：`山高人为峰，客至心自明` / `欢迎回来，董事长`；
  - 其他角色（运营 / 客服 / 充值管理员）→ **一行**：`欢迎回来`。
- **节奏（毫秒，逐值固定）**：第 1 行淡入 **250** → 停 **700** → 第 2 行淡入 **250** → 停 **900** → 整屏淡出 **300** = **总 2400ms**（落在"约 2.4–2.8s"区间内）。
- **可跳过**：点击任意处 / 按任意键**立即结束**（不等满时长）。
- **排版**：全屏**纯黑底 `#000`**（刻意不用页面近黑——要的就是"全屏纯黑"）、居中、**44px / 800 / 白字**（≤1366 宽降到 40px 防换行）、两行间距 20px，下方一条 **64px 宽 2px 高的冰雪蓝细线**（唯一点缀）；**没有插画 / 光斑 / emoji**。每次登录都播一次（不做"只播一次"）。
- 分段常量 `WELCOME_TIMING`、总时长 `WELCOME_TOTAL_MS`（分段相加）与文案常量同在这一个文件里；全屏覆盖层实现在 `components/WelcomeSplash.vue`，**改节奏只改常量文件**。

### 5. 工作台（首屏）

- **快捷导航六宫格**：按权限点过滤后取**前 6** 个入口，每格 = **彩色线性图标卡 + 一行说明**（说明写清去哪做什么，不写空话）。
- **数据概览卡**：小标签「**累计 / 今日 / 实时**」+ 大数字 + 一行说明（数字口径写在说明里，不靠猜）。
- 数据**全部走现成接口**（`/admin/commission/stats`、`/admin/users`、`/admin/workers`、`/admin/wallets`、`/admin/orders?status=pending_take`、`/admin/recharge/requests?status=pending`、`/admin/complaints`）——**后端一行未改、没有新造聚合接口**，也没有为展示造数。

### 6. 已知取舍
