3. **服务端 `/public/players` 微缓存移除（实时化）**
   原先响应拦截器给公开接口挂了微缓存；已移除 → `worker_division_permission` **每次请求实时查库**。
   实测：管理端刚授权/刚撤销，**3ms 内**下一次请求即反映新权限。

4. **客户端最后一层缓存修复（本轮核心）**
   问题：服务端已实时，但 core 把 `/public/players` 配成 **`ttlDict`（10 分钟）**，且「找陪玩」页
   拼请求**没带 `forceRefresh`**（只有「指定护航员」弹层带了）→ 管理端改完权限，老板进「找陪玩」
   **最长 10 分钟仍可能看到旧名单**。
   修法（最小 + 语义正确，两条并用）：
   - `apps/packages/core/lib/src/api/api_cache.dart`：把 `/public/players` **从字典档登记中删除** → 落回
     默认 **45s 列表档**（它随授权状态变化，属"因人而异、随时效变"的准实时数据，不是管理端低频配置）；
   - `apps/boss-app/lib/pages/players_page.dart`：**进入页面 `force: true`** + 把 `force` 透传到
     `forceRefresh`（下拉刷新原本就想强刷，此前**没透传 = 空转**）；
   - 其余接口 TTL **一条未动**，并已用断言钉死（`/public/games`、`/public/categories`、`/public/home`、
     `/public/announcements`、`/divisions/grouped` 仍为字典档）。
   - 测试：core 新增 1 条（TTL 断言）、老板端新增 2 条（进入强制回源 / 下拉 force 真透传）；
     **并做了反向验证**：把 `forceRefresh` 改回 `false` → 两条测试**都变红**，证明不是空断言。
   - 提交：**`18442cd`**（6 个文件，+229/−4）。
