## 二、设计定案（I 系列）关键结论
负责人逐轮确认的最终形态：

- **视觉**：F 主题（青蓝渐变主视觉 + 卡片 + 彩色标签胶囊 + 圆形雪山下单浮标 + 底部凸起＋）
- **结构**（后几轮确认的修正全部保留）：
  1. 同一入口只出现一次 → 顶部 `首页 · 排行榜 · 玩家圈 · 公告`；底部 `服务 · 订单 · ＋ · 消息 · 我的`
  2. 不存在的不显示 → 和平精英只有手游，**不出现「端游」选项**（服务端 `platformCount=1` 时客户端不渲染平台筛选）
  3. 模块不混装 → 消息页**只有 好友私聊 / 客服 / 打手**
  4. 只有官方自营 → 首页只有「祁连山官方」，无推荐/关注俱乐部等多档标签
  5. 陪玩展示极简 → **只有 名字 + 介绍**（介绍由管理端填写），禁 明星陪玩/大神/单考/双考/空闲/忙碌/等级/评分/单价/下单人数/语音时长/标签/分部副标
- **去 AI 味**：渐变只做主题点缀、标签只给必须区分的项、左对齐为主、数据拟真（`2,847 单`、`9:00-次日 2:00 在线`、`不接急单`）→ 规范见 `docs/21-反AI味设计规范.md`

### 刻意不复刻的三处（做假比不复刻更糟）
| 设计稿元素 | 为什么不照做 | 建议 |
|---|---|---|
| 玩家圈「攻略 / 组队」筛选胶囊 | `forum_post` 表**没有话题/标签字段**，做了就是假筛选（点了没作用） | 需要新增话题字段 + 发帖选话题 + 按话题过滤（约 1 轮工作量），批准后即做 |
| 帖子「送礼」互动 | 后端**没有帖子打赏接口**，放假按钮会误导 | 同上，需先定积分礼物规则（属积分账务变更，按铁律需负责人确认） |
| 排行榜「好评榜 / 人气榜」 | 无评分 / 人气数据源（榜单目前只有真实成交金额） | 有评价体系后可加；当前保留「接单榜 + 周榜/月榜」这套**全部真实可用**的切换 |

## 八、本轮踩坑与结论（避免下次重犯）

| 坑 | 结论 |
|---|---|
| `lucide_icons` / `phosphor_flutter` / `font_awesome_flutter` 三个图标包全部不可用 | 新版 Flutter 的 `IconData` 是 `final`，继承它的第三方包会「装得上、analyze 不报、一编译就炸」；**只用不继承 IconData 的图标来源**（已改用 Flutter 内置 Material 图标） |
| Gradle 下载超时导致构建失败 | 默认 `.gradle` 目录残留 0 字节 `.part`；**构建必须设 `GRADLE_USER_HOME=D:\fish\.gradle-home`** |
| PowerShell 会拆坏中文/括号/多行参数 | 提交用 `scripts/tmp/commit.ps1`（`-F` 文件方式）；日志追加改用 Node 写 UTF-8，不用 `Add-Content` |
| 数据库口令在 shell 中被拆 | 统一用 `MYSQL_PWD` 环境变量传密码 |
