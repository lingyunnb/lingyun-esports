## 四、货架数据来源（**实测**，不是推测）

### 4.1 `GET /public/products` 真实支持哪些参数（2026-10-15 curl 实测）

`server/src/modules/product/public-catalog.controller.ts:36-50` 只声明 5 个参数：
`gameId` · `categoryId` · `divisionId` · `page` · `pageSize`

实测（各试 1 次，比对返回顺序）：

| 试的参数 | 结果 |
|---|---|
| `sort=sales` / `sort=salesCount` / `sort=newest` / `sort=createdAt` / `sort=recommend` / `sort=price_asc` | **全部被忽略** |
| `sortBy=salesCount` / `order=desc` / `recommend=1` | **全部被忽略** |
| `shelf=recommend` / `shelf=hot` / `shelf=newest` | **全部被忽略** |
| `keyword=` | **被忽略**（接口没有 keyword，与 `services_page.dart:404-408` 的判断一致） |
| `divisionId=1` | ✅ 生效（total=8） |

13 组试验的返回顺序**逐条一致**（168 → 137 → 145 → 144 → 143）→ **服务端当前没有任何排序能力**，默认序也不是 id/时间倒序。

返回字段实测 17 个：`id · name · subtitle · gameId · categoryId · divisionId · price · priceUnit · estimateDurationMin · salesCount · coverMediaId · badgeText · weeklyLimit · listName · weeklyLimitByQuantity · coverUrl`
**没有 `createdAt` / `updatedAt` / `sortOrder`**。

### 4.2 三个货架的落地口径

| 货架 | 口径 | 首版可否 0 服务端改动 | 证据 |
|---|---|---|---|
| **为您推荐** | `product.badgeText` 非空 | ✅ **可以** | 实测 8 条里 2 条有 `badgeText="董事长推荐"`（id 168 / 137） |

**首版路径（推荐先上）**：`_load()` 里加 1 个 `GET /public/products?pageSize=50`（按当前分部）→ 客户端按上表三口径切片。

## 六、五个待负责人拍板的设计决策

1. **货架标题：A 套（文字标题 + 品牌色小标）是推荐项。** 理由：① 零新增图片资产，改文案不改图；② 文字可被搜索/无障碍读出，标题变长不会因 166rpx 固定宽度挤爆；③ 与「白底为主 + 实色」一致（图形标题通常还要加底/描边才压得住）；④ 将来加第 4 个货架不必再出图。B 套代价：3 张 ×2 倍图资产 + 改一个字要重新出图。**折中版**：只给「为您推荐」用图形牌（B 的最小剂量）。
2. **货架内用纵向 ListCard 行（否决横向滑动）。** 理由：实测最长商品名 **46 字**（`44.6博弈鹰雕单（出反现小金人+金aug或雪隼）不出保1200w[老板必须全程录屏不录开出不算]`），横向卡宽 150–180dp 只能放 2 行 × 8 字 = 16 字必然严重截断；价格与计价单位（`/单`、`/局`）需要横向对齐才有比价秩序；纵向行能天然承载"无封面"降级。首屏高度靠"每货架行数 + 查看更多"控制，不改横向。
3. **货架卡不放封面列。** 实测 8 个在架商品里 7 个 `coverUrl=null`，放封面列会出现 7 个空框（违反「不存在的东西不出现」）；且封面列再占 88dp 会让名称更早截断。**封面留给商品列表页与详情页**；若管理端给 ≥80% 商品配齐封面，再启用「带封面变体」（`compare.html` 已留说明）。
4. **宣传图下面第一块是货架，分部后移。** 理由：本轮目标就是货架结构，首屏价值最高的是能直接下单的商品；分部是筛选/导航而非内容，从货架点进商品即可下单，下单页本身也有分部/平台选择；竞品首页第一块内容也是货架。分部卡不删，且「查看更多 → 商品列表页」内仍有分部筛选 → 入口不重复。
5. **首页不加「陪玩推荐位」（本轮）。** 理由：① 底部「＋下单」/找陪玩页已存在，首页再放陪玩行 = 同一入口二次出现（结构规则 1）；② `/public/players` 实测 13 人里 10 个是 `wtest_*` 测试账号、`intro` 全空 → 现在放上去就是"不存在的东西"；③ 四徽章涉及 `isfwzx` / `isyzpw` / `jdsta` 三类新字段与管理员配置，属负责人单独批的范围（结构规则 6）。若要放，最小形态 = 一行标题 +「让祁小山挑」入口（不列人）。

**⚠️ 定案冲突需二选一**：**紧贴体（0 间距）归宣传图（2026-10-14 定案）还是归充值入口条（2026-10-06 定案）？**
本设计图按 **10-14 定案：宣传图紧贴导航**（导航底距 = 有宣传图 ? 0 : 12）绘制；若按 10-06 定案，则充值条上移紧贴导航、宣传图退到条下方（间距 12）。
