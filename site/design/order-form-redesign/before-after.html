3推荐方向与理由

  • 推荐方向 A（一卡多行），理由三条：
  • ① 它才是"发丝线"的正确用法：docs/21 明写「列表用发丝线、列表优先于卡片阵」，而本页现状恰好是"把表单拆成卡片阵"。一张卡 + 发丝线分行 = 把 5 个问题一次解决，且不需要新增任何分组名（后台没给语义）。
  • ② 与刚定案的「我的」页同族：site/design/profile-redesign/B.html 的语言就是「卡片 + 卡内发丝线行 + 左标签右值」，下单页跟随它 → 全站一个语言，不再是"一半精修一半原样"。
  • ③ 省近 50% 垂直空间：字段越多收益越大（9 字段省 482dp），后台随时可能加字段，方向 A 的收益随字段数线性增长。
  • 方向 B 的价值：改动面最小（_card 一处 + 循环微调），如果负责人希望这一版"只换皮不动骨架"，B 是零风险选项；但省空间只有 15.5%，"碎片化"这条根因（问题 ③）仍然存在。
  • 若两方向都不批：最低限度建议先落 B 的 focusedBorder（问题 ②）与错误文案（问题 ⑤）——这两条是功能可用性问题，不只是好看问题。

6「聚焦竖条」是否触红线？（主动说明 + 替代方案）

  • 我们的判断：不触线。 docs/21 禁的是「每张卡左侧一条彩色竖条」——那是装饰性的、静态的、每张卡都有的彩条（"过时模板签名"）。方向 A 的竖条满足三条与它相反的性质： ① 不是每行都有，只有正在编辑或报错的那一行有；② 随状态出现/消失（失焦即消失，AnimatedContainer 120ms 过渡）；③ 宽度只有 2dp，且是主色 token 而不是"彩虹分色"。
  • 但它确实是一个"弱信号"：如果负责人觉得"看起来像彩条"，替代方案有三个（任一即可，均不依赖颜色）：
    • 替代 1（推荐兜底）：去掉竖条，改用「行底色 #F8FAFD + 标签加粗转主色 + 输入行尾部一个 14dp 主色线性光标」表达聚焦 —— 只靠字重 + 底色。
    • 替代 2：竖条改为 2dp 圆点前缀（行首一个 5dp 圆点，聚焦/报错时才出现）。
    • 替代 3：竖条只保留给错误态（错误必须有形状信号），聚焦态只用标签加粗 + 底色。
  • 无论选哪一版，聚焦与错误都同时具备"颜色之外的信号"（字重 / 图标 / 文案 / 底色），满足"不能只靠颜色"的硬要求。
